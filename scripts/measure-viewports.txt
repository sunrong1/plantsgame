# Story 1.19（组 H / AC-H1、H3、H4）的**布局量测矩阵**；Story 3.5 扩到 16 个
#
# ── 这个文件是什么 ────────────────────────────────────────────────────────
#   `npm run verify:portrait`（= `scripts/verify-portrait-layout.ts`）在跑完
#   800×1280 的 8 条判据之后，会**逐个**在这里列出的视口上再量一遍，
#   并把结果打成一张表（**每个视口两个相位**：答题相 / 建造相）。
#
# ── ⚠️ 它是「量测」，不是「判据」 ──────────────────────────────────────────
#   那 8 条判据逐字写着「本脚本只量 800×1280 这一个视口」⇒ 它们**不参与**
#   额外视口的判定，额外视口**只产出数字**，由人抄进 story 文档的实测表。
#   ⇒ 退出码只由 800×1280 那 8 条决定。
#   📎 Story 3.5 的 **L2 逐视口层**（三条新判据在每个视口**求值**并报数）
#     也**不进退出码** —— 「不进门 ≠ 不报」：✘ 会逐条打印，并要求写进 story 文档。
#
# ── 为什么是这 16 个 ──────────────────────────────────────────────────────
#   竖屏 7 个 + 横屏 9 个：
#   · 竖屏 7 个：AC-H4 逐字点名「**竖屏七个尺寸**零回归」；
#   · 横屏 7 个：AC-H1/H3 的横屏可用性（Task 6 当时量的是同样这 7 个）；
#   · 横屏 +2 个（**Story 3.5 / B7**）：
#     · `1280x660` —— **DF-087 逐字点名的那个形状**（矮横屏视口）
#       ⇒ 它的结论**可以当设备形状的结论**看；
#     · `1280x713` —— **「浏览器标签页模式」的降级形态**（= 1280×800 设备
#       **减 87px 浏览器工具栏**，与 1.19 实测的 87px 偏移同源）
#       ⇒ ⚠️ 结论**必须标注「降级形态，非设备真实尺寸」**，不许当设备结论。
#   ⇒ 布局一改（选项数、战场尺寸、题卡高度），这张表**必须整体重量**，
#     否则「零回归」这句话没有当下的实测值背书。
#
# ── 写法 ─────────────────────────────────────────────────────────────────
#   一行一个 `宽x高`，`#` 开头是注释，空行忽略。
#   ⚠️ **不许加后缀** —— `parseViewportLine` 只认整行 `WxH`，
#     写 `1280x713 measure-only` 会直接抛「视口写法看不懂」。
