# Story 1.19（组 H / AC-H1、H3、H4）的**布局量测矩阵**
#
# ── 这个文件是什么 ────────────────────────────────────────────────────────
#   `npm run verify:portrait`（= `scripts/verify-portrait-layout.ts`）在跑完
#   800×1280 的 5 条判据之后，会**逐个**在这里列出的视口上再量一遍，
#   并把结果打成一张表。
#
# ── ⚠️ 它是「量测」，不是「判据」 ──────────────────────────────────────────
#   那 5 条判据逐字写着「本脚本只量 800×1280 这一个视口」⇒ 它们**不参与**
#   额外视口的判定，额外视口**只产出数字**，由人抄进 story 文档的实测表。
#   ⇒ 退出码只由 800×1280 那 5 条决定。
#
# ── 为什么是这 14 个 ──────────────────────────────────────────────────────
#   竖屏 7 个 + 横屏 7 个，全部来自 Story 1.19 的实测表：
#   · 竖屏：AC-H4 逐字点名「**竖屏七个尺寸**零回归」；
#   · 横屏：AC-H1/H3 的横屏可用性（Task 6 当时量的是同样这 7 个）。
#   ⇒ 布局一改（选项数、战场尺寸、题卡高度），这张表**必须整体重量**，
#     否则「零回归」这句话没有当下的实测值背书。
#
# ── 写法 ─────────────────────────────────────────────────────────────────
#   一行一个 `宽x高`，`#` 开头是注释，空行忽略。
