I want 答错了会失败、能重打，答对了能往下走,
So that 我知道读书是有尽头的，而且没听懂可以再来一次。

### 裁决 4 —— 🔥 重打**不读档**，且必须**新增第 6 个写盘点**

**这一条是本 story 最重要的裁决，两个方向都要做对。**

**（a）为什么 `restartLevel()` 门面绝不调 `enterLevel()`**

`deferred-work.md` 的 1.15 第 4 条要求「新增的『回到战场』路径必须走 `enterLevel()`
或显式调 `restoreFromSave()`」。那条要求的前提是「回到战场 = 恢复上一局」。
**重打不满足这个前提**：盘上此刻存的正是刚刚 `level-failed` 的那份 state。

若重打走 `enterLevel()`：`readSave()` 把那份失败态读回来 → 覆盖掉 `restartLevel()` 的结果
⇒ **孩子点了「再试一次」，什么都没发生。** ⇒ 重打**禁止**读档。

**（b）🔥 为什么必须新增第 6 个写盘点**

1.15 裁决 6 的 5 行表逐字如下（`core/effects.ts` 块 ④）：

| 相位 | 写盘？ | 1.15 给的理由 |
|---|---|---|
| `awaiting-answer` | ❌ | 「刚 CONTINUE 出来，与上一份 round-over 存档内容相同」 |
| `awaiting-build` | ✅ | AC 逐字要求「包括当前处于 awaiting-build 的局面」 |
| `resolving` | ❌ | 「真实一帧，用户看不到也退不出」 |
| `round-over` | ✅ | 「每个回合结束」的主路径 |
| `level-failed` | ✅ | 「不写的话失败后退出重进会退回上一回合」 |
| `level-complete` | ✅（存 `null`） | 「局末清空战场」 |

重打后的相位是 `awaiting-answer` ⇒ 按表**不写盘** ⇒ 盘上仍是失败态 ⇒
**FR51「战场状态在局末清空，不跨局保留」被破**：一份 hearts=0 的失败战场跨局活到了下一局。

⇒ **在 `core/effects.ts` 块 ④ 加一条按 `action.type` 驱动的判据**：

```ts
// 🚨 1.16 追加 —— 表的**例外行**，不是矛盾（裁决 4）
if (action.type === 'RESTART_LEVEL') {
  effects.push(save(next))
}
```

⚠️ **它为什么不是 `awaiting-answer` 那一行的反例**：那一行的理由逐字是
「**刚 CONTINUE 出来**，与上一份 round-over 存档内容相同」——
**重打不是 CONTINUE**，盘上那份是**失败态**而不是「上一回合」⇒ 理由不适用。
⇒ **必须在代码注释里写清这一句**，否则下一个人会把它当成矛盾去「修」，把第 6 行删掉。
（R-37 要求这件事只写一次，所以这句理由写在 `effects.ts` 里，story 文档只留指针。）

⚠️ **别把它塞进 `store` 门面**：G86 逐字钉死「只有 `effects-runner.ts` 能调 `writeSave`」，
门面直接调会当场破守卫 —— 那是**有意的**，判据住在 `core/effects.ts` 里（R-04）。

### 裁决 5 —— 终态画面：**单个全屏浮层 `LevelOutcome.vue`**，不扩 `view` 联合

**为什么不是两个独立视图**：`view` 联合从 `'start' | 'level'` 扩成三态会牵动

那条注释正是 1.10 的设计意图：**战场任何时候都在**。
浮层方案保住了它：战场照常渲染（终态下是空网格，符合 AC-F4「不得白屏」），浮层盖在上面。

而 NFR13 的精神是「孩子面前不出现任何让他困惑的东西」。全屏浮层是唯一无歧义的形态。

**组件落点 `components/hud/`** —— 它与 HUD 同性质（同一局的状态的另一种呈现），
不是新的视图层。⚠️ 若你认为该放 `components/level/`，先读 `docs/rules/README.md` 的
R-08：依赖方向只能向下，**组件间不互相 import** ⇒ 新组件只能 import `app/store` 与 `core`。

### 裁决 8 —— 三个组件本地 ref 的复位判据是 **`turn === 1`**，不是「相位变了」

`QuestionCard.vue` 有三个组件本地 ref（`lastQuestion` / `pickedOptionId` / `spokenEntryId`），
**今天没有一条复位路径**。1.11 `[CR]` 逐字列了后果：`spokenEntryId` 让重打后的首题**无声**；
`pickedOptionId` 让失败时仍挂上一题的绿色「答对了 ✓」。

**难点**：怎么知道「现在是重打之后」而不是「推进到下一题」？
两者都是「相位从 `awaiting-answer` 离开又回来」。

⇒ **判据：`state.turn === 1`**。因为 `createInitialState` 逐字写 `turn: 1`，
而正常 `CONTINUE` 推进后是 `state.turn + 1 ≥ 2`。**这是唯一能从 `State` 里读出来的区分。**

| 场景 | `turn` | 判据 |
|---|---|---|
| 重打后的第一题 | `1` | 复位三个 ref |
| 开局第一题 | `1` | 复位（本来就是空的，幂等） |
| CONTINUE 推进到下一题 | `≥ 2` | **不复位**（否则答完的题会被重新显示） |

⚠️ **别用 `masteredEntryIds.length === 0` 当判据** —— 那在重打后成立，但 `turn` 更直接，
且不依赖「重打一定清空掌握记录」这个需要额外证明的事实。

### 裁决 10 —— 🔥 进关单元号由 `progress.currentUnitIndex + 1` 决定

**洞 3 的修法。AC 逐字要求「自动进入下一单元」，所以这条接线归本 story。**

现状：`store.ts` 的 `initialState()` 逐字用 `FIRST_UNIT_NUMBER`（写死 1）组装，
而 `FIRST_UNIT_NUMBER` 的注释逐字说「这里写死 1 而不是做成配置，是**有意的**」。
⇒ 不改这个常量（那是「不建选关」的表达），**改的是「进关时用哪个单元号」**：

- 模块求值期建的那份 `state` 仍按 `FIRST_UNIT_NUMBER`（无存档时的开局，不变）。
- `restoreFromSave()` 在 `progress.value = saveFile.progress` **之后**，
  若 `currentGame === null`（局末清空），**用 `saveFile.progress.currentUnitIndex + 1` 重新组装**。
- 若 `currentGame !== null`，走原路径（断点续学优先，FR60）。

⚠️ **换算是 `+1`**：`currentUnitIndex` 是 0 基、`unitNumber` 是 1 基（AC-B2）。

⚠️ **组装失败要降级而不是崩**（NFR13）：目标单元取不到时退回 `FIRST_UNIT_NUMBER`
的既有开局，并记一条 WARN —— 与 `LevelView.vue` 的 `unitTotal` 那个 try/catch 先例同型。
⚠️ **不要抛**：`initialState()` 现在抛的错是 `[app] 组装单元 N 的初始 state 失败…`，
而它只在开局路径有意义；进关路径抛会变成孩子点「开始游戏」就白屏。

**Epic 1 里这是恒等变换**（`currentUnitIndex` 恒 0 ⇒ `+1` 恒 1）⇒ **构造上不可达**。
⇒ 因此**必须用单测直接喂一个非零 `currentUnitIndex`**（AC-F2 同款要求），
否则 G95 恒绿（R-51）。

### 裁决 11 —— 🔥 改判据：`runEffectsFromStore` 收到**结算后**的 `progress`

**洞 2 的修法。这是本 story 唯一一处改动既有判据，按 R-57 逐条留痕。**

**被改的判据**：1.13 AC-B3 逐字「`advanceProgress` 排在 `state.value = next` **之后**是刻意的」，
1.15 的偏离 3 由此而来（「落盘比内存少一条本次新掌握的词」）。

**为什么必须改**：`applyAction` 的第 3 步（effects-runner）在第 7 步（`advanceUnit`）之前。
`masteredWordIds` 少一条，下次进关补得上；
**`currentUnitIndex` 少一次推进，关掉页面就永远补不上** ⇒ 通关后关页面，进度退回上一个单元。
这正是 R-06 逐字警告的「静默丢进度」形态。

**怎么改（且不违反 1.13 的**理由**）**：1.13 AC-B3 的理由逐字是
「**必须读 `next`，读 `prev` 就永远慢一拍**」—— `next` 在第 2 步就已经有了，
所以「读 `next`」这条**理由**完全保留；被改的只是「**排在赋值之后**」这条**字面口径**。

```ts
const prev = state.value
const next = reduce(prev, action)
// 🔥 1.16 裁决 11：先算「本局结算后的进度」，让写盘看到它
const nextProgress = advanceUnit(advanceProgress(progress.value, next), hasNextUnit(next))
runEffectsFromStore(action, prev, next, nextProgress)   // ← 第 4 参从 progress.value 改成 nextProgress
state.value = next
clearSelectionIfLeavingBuildPhase(next)
```
