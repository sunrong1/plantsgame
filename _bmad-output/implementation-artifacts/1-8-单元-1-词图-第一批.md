## Story

As a 孩子,
I want 听到 `dog` 时能看见一只清楚的狗,
So that 我能把听到的声音和看到的东西连起来 —— 这是这个游戏教我的全部方式。

**本 story 的交付形态是「5 张校准批 + 一条可复用的守卫 + 一份产能实测」，不是「画完单元 1」。**
画完 5 张后有一道**决策门**（AC-12），用真实耗时决定要不要在本 story 内继续画到 30 张。

### 组 B：词图规则与守卫

**AC-3（新规则，裁决 2）** 词图**不得含 `<text>` / `<image>` / `<foreignObject>`**。
- 判据写在 `docs/art-direction.md`，**并在该文件文首「真被守着吗」对照表加一行**
  （守它的是什么 / 怎么证它会红）
- 守卫落在 `tests/assets/asset-geometry.test.ts`，编号沿用体系取 **G10**
- **配一次变异**：把一张词图塞进 `<text>`，必须变红
- ⚠️ **守卫先于图**：先写守卫，并看着它在**当前 30 张占位图上先红**（占位图全都有 `<text>`），
  再改图。Story 1.7 的原话：「先画图后补守卫，很容易让守卫按『手头这些图长什么样』去写，
  写出只对当前文件成立的断言。」
- ⚠️ **G10 与 G9 不矛盾，别合并**：G9 钉的是「§3.2–§3.7 不约束词图」，
  G10 是一条**独立的教学内容硬约束**（听音→识物，答案不得以任何形式出现在选项上）。
  词图**照样可以用 `<path>`、可以贴边、可以重心偏移**。把这两件事混成一条会让下一个人
  以为词图被 §3 绑住了。

**AC-4（答案泄漏闭合）** **30 张词图全部不含 `<text>`** ——
本 story 画 5 张正式插画，另外 **25 张把 `<text>` 剥掉**，保留「一眼可辨是占位图」的外观
（对角线灰纹 + 虚线框）并在 XML 注释里保留 `PLACEHOLDER` 说明。

> 🔥 **为什么不能只让 5 张合规就收工**：剩下 25 张占位图各自把 `entryId` 画在图上
> （`deferred-work.md:411-417`），而 Story 1.19 首次试玩是 **Epic 1 的生死线**。
> 若占位图拖到 1.19 仍带答案文字，**试玩结论会被「答案直接印在选项上」污染**。
> 本 story 把这条彻底闭掉，成本只是 25 次机械删标签。

**AC-5（画布层硬约束，5 张逐条过）** 5 张正式插画全部满足：
`viewBox="0 0 512 512"` + `width="512" height="512"` + **透明底** +
文件名 = 词条 id + 路径 `public/assets/words/unit-01/<entryId>.svg` +
URL `/assets/words/unit-01/<entryId>.svg` + **单文件 ≤ 10KB**（架构 `:374` 的量级是 2-10KB）。

**AC-6（`validate:content` 通过）** `npm run validate:content` 对本批全部通过，exit 0。

### 组 D：5 张校准批本身

**AC-8** 交付 **5 张**正式插画，覆盖难度谱（**刻意不是随机抽样**）：

| # | 词条 | 难度档 | 为什么选它 |
|---|---|---|---|
| 1 | `u1-dog` | 中（有机曲线） | `<path>` 的主战场：耳朵、尾巴、毛发轮廓全是曲线 |
| 2 | `u1-ball` | 低（几何体） | 纯圆 + 弧线，是本批的**下限**。若这张也画很久，说明成本不在「难」上 |
| 3 | `u1-teacher` | **高（人物）** | 人形是公认最难画的具象目标；包含手势/教具等组合元素 |
| 4 | `u1-three` | **高（抽象·数量）** | 数字词的画法本身就是「画 3 个东西」，与具象词完全不同套路 |
| 5 | `u1-happy` | **最高（抽象·情绪）** | 最可能卡住的一张。**故意放在最后** —— 若前 4 张顺利而它卡住，说明「抽象词」是产能真正的分水岭，这条发现本身就要上报 Story 2.1 |

> **为什么刻意包含两张最难的**：若这 5 张能在预算内画完，剩余 25 张（具象动物 / 人物 / 日常物品）
> 只会更容易，决策门就是安全的。反过来，若先画简单的、最后才撞上抽象词，
> 就会得到一个**系统性偏乐观**的产能估计。

**AC-9** 每张画完后做栅格化自检并记录结果，**两档尺寸 × 两档模式**：
180px 与 **48px**（48px 才是卡面格子的实际量级，`--touch-min: 48px`）× 彩色与灰度。

**AC-10** 每完成 2-3 张**停下来校准一次**（`epics.md:969-970` 原文要求），
把实际耗时与「20 分钟/张」的估算对比，偏差显著就当场记录。

| `viewBox` | **`0 0 512 512`** |
| 输出尺寸 | **`width`/`height` 均为 512**（必须与 viewBox 一致，否则浏览器按 CSS 拉伸，图会糊） |
| 背景 | **透明底，不画统一背景** |
| 文件名 | **= 词条 id** |
| 目录 | `public/assets/words/unit-<NN>/<entryId>.svg` |
| URL | `/assets/words/unit-01/u1-dog.svg` |

**透明底不能当儿戏**：判据是「**盖住整张画布就算**」，覆盖 rect/ellipse/circle/polygon
+ 百分比 + 出血 + 3 位 hex（变异 M13 验证过）。「透明底 + 不统一背景」在本题里不是两个选项 ——
统一背景必然不透明，而不透明背景的图没法按主体抠轮廓，
那是 Story 2.1 程序化生成评估的**必要前提**（`art-direction.md:85-91`）。

### 3. 词图的形状与引用模型（Story 1.6 已做，本 story 只读不改）

- **词图挂在选项上，不挂在词条上**：`ImageOption` 有 `imageSrc`，
  恒等于 `/assets/words/unit-01/<词条id>.svg`
- `ENTRY_ID_PATTERN = /^u\d+-[a-z0-9]+(?:-[a-z0-9]+)*$/` —— **单元前缀不是排版偏好**：
  录音目录 `audio/voice/` 不按单元分层，id 不带前缀则不同单元的同名词撞名 → **发错音**（静默严重错误）
- **图片不进 JS bundle**（架构 `:304`）：`<img src>` 消费，**不要 `import`、不要 base64 内联**
- **只有单词卡需要词图**：关键词卡 / 回应卡的选项是文字（`TextOption` 无 `imageSrc`）
- **文件名一个都不许改**：改了 `wordImageProblems` 的存在性检查会红，且 120 处 `imageSrc` 也要同步

### 5. SVG 写作禁忌（1.7 真的踩过，不是理论）

**① XML 注释里不许出现连续双短横。**
1.7 在塔图注释里写了 `--color-tower-shooter` 来说明色值来源，
结果**三张塔图在浏览器里一张都渲染不出来**（按 `image/xml` 解析报 parse error），
而当时 **G1–G7 全部绿着** —— 守卫查的是「属性对不对」，文件根本没被解析时属性当然是对的。
⇒ **写注释时提 token 名，把前导的两个短横省掉**（照抄 `direct.svg` 第 10-14 行的写法：
「色板：`#09428c` = tokens.css 的 color-tower-shooter」）。
⚠️ 中文破折号 `——`（U+2014）是安全的，**别手抖打成 ASCII `--`**。

**② 属性正则必须用 `(?:^|\s)` 不能用 `\b`。** `\bwidth` 会命中 `stroke-width`
（`validate-content.ts:411-422`）。

**③ 任何 SVG 正则匹配前必须先 `stripXmlComments()`。**
文件头注释里逐字写着「viewBox 0 0 512 512」，不剥注释就匹配 `viewBox`，
**所有守卫在所有文件上恒绿** —— 那不是「守卫不严」，是**守卫恒等于真**，比没有守卫更坏。
✅ `stripXmlComments` 已从 `scripts/validate-content.ts` 导出，**复用，不要重新实现**。

**④ 属性值里出现 `>` 会截断 `<svg>` 开标签**（P2-4 / AC-1）。
`aria-label` / `id` 是高发区。

**⑤ 单引号属性。** 1.7 的结构签名解析器曾只认双引号，Inkscape / Illustrator 导出的是单引号
（已修，`[CR]` 2026-10-14）。本 story 手写 SVG 用双引号即可，但改 P2-2 的扫描器时
**要注意它也得认单引号**，否则守卫会对单引号文件恒绿。

### 6. 栅格化自检怎么做（照 1.7 的做法）

1.7 用 Chromium 把四张塔/僵尸 SVG 栅格化看过：180px 与 48px 两档、彩色与灰度两档。
**48px 是本 story 最该看的一档** —— 那是卡面格子的实际量级（`--touch-min: 48px`）。

1.7 的目视收获值得先读（避免重蹈）：

⇒ **大图上看着对不代表 48px 上对。** 每张都要两档都过。
