## Story

As a 孩子,
I want 战场上有一株清楚的植物在替我打僵尸,
So that 我能看见我的防线长在哪里 —— 答对换来的东西得看得见。

**这是 Epic 1 第一个「看得见」的 story。** 前面六个 story 全部是看不见的地基；
从本 story 起，孩子第一次能在屏幕上认出「这是我的直射塔」。

## Acceptance Criteria

### AC 组 1 —— 四个 SVG 资产

**AC-1** `public/assets/towers/` 下**恰好** 3 个 `.svg`，文件名 = `direct.svg` / `slow.svg` / `aoe.svg`。
「恰好」是双向的：**多一个文件或少一个文件都要报错**（FR70「美术资产按塔型制作，
不随词数增长」的**唯一可机器判定形式** —— 只查「三个都在」的话，
哪天有人给每个词配一张塔图，这条守卫照样全绿）。

**AC-2** `public/assets/zombies/` 下**恰好** 1 个 `.svg`，文件名 = `zombie.svg`（FR71）。
僵尸 id 未在任何规划文档里定义过，本 story 裁决取 `zombie`，理由：它是**通用敌人**，
文件名里不该出现「某一关」「某一型」这类暗示它会分化的词。若将来要第二种僵尸，
改为 `zombie-<type>.svg` 并同步改守卫（见 Dev Notes §范围外）。

**AC-3** 四张 SVG 的几何规格**全部**满足：

| 项 | 值 |
|---|---|
| 格式 | SVG |
| `viewBox` | `0 0 512 512` |
| `width` / `height` 属性 | 均为 `512`（**必须与 `viewBox` 一致** —— 不一致时浏览器按 CSS 拉伸，图会糊。`docs/art-direction.md:41` 同款理由） |
| 背景 | **透明底**，无覆盖全画布的不透明 `<rect>` |
| 单文件体积 | **≤ 10KB**（架构 `:374` 给的量级是 2-10KB；超过即偏离） |

> 与词图共用同一套画布规格，是刻意的：**§3 构图规范对塔/僵尸/词图三者是同一份**，
> Story 1.8/1.9 画词图时直接复用本 story 的模板与规范，不另起一套。

**AC-4** 🎯 **塔的**主体填充色 = 对应 `--color-tower-*` 的**字面 hex 字符串**；
**僵尸的**主体填充色 = `--color-zombie` 的字面 hex。

**为什么是字面 hex 而不是 CSS 变量** ⚠️ 这是本 story 最重要的一条技术决策：
SVG 经 `<img src="...">` 加载时是**独立文档**，**无法继承 `:root` 的 CSS 变量**。
架构 `:304`「图片不进入 JS bundle」已把塔/僵尸钉在 `public/` + `<img>` 这条路上，
所以「用 CSS 变量画 SVG」物理上不成立。

⇒ **代价是色值有两处副本（`tokens.css` 与 SVG 文件），必须有守卫锁住一致性**（AC-16）。
这是本项目接受的既有纪律的延伸，不是新的债：`tokens.css` ↔ `docs/art-direction.md`
↔ `palette.test.ts` 本来就是三处，靠测试锁死。SVG 是第四处，测试同样锁。

**AC-5** 🎯 **三个塔型在「去掉全部颜色之后」仍然可区分。**

这是 `docs/art-direction.md:117-122` **明文交给本 story 的兜底责任**，原文：

> 塔与塔之间没有 3:1 的明度对比，只有色相。……**代价**：灰度打印或完全色觉障碍下三塔不可分。
> **兜底责任在 Story 1.7**：美术必须另外提供形状/轮廓差异，不能只靠颜色区分塔型。

**为什么这条不能靠自觉**：三个塔底色都在 L ≤ 0.09 的深色区
（0.058 / 0.062 / 0.064），**灰度化后三者几乎同值** —— 也就是说
「颜色以外没有任何区别」这件事在数学上会静默通过所有颜色类测试。
「只换颜色不换形状」是复制粘贴时最自然发生、也最不容易被 review 看出来的失误。

⇒ 本 story 不只要求形状不同，还要**用 AC-16 的结构签名守卫把它钉住**。

**AC-6** 四个 SVG 通过 `<img src="/assets/...">` 消费，**不 `import`、不 base64 内联**
（架构 `:304`「图片不进入 JS bundle」；`public/` 下的文件由 Vite 原样拷贝，
天然可被 Service Worker 静态缓存 —— 这是 PWA 决策 8 的基础，见 `:965`「启动时缓存当前单元资源」）。

**AC-7** **不新增任何依赖。** SVG 几何检查用手写解析，不用 XML 解析库（见 AC-15）。

### AC 组 2 —— 构图规范（`docs/art-direction.md` §3 定稿）

**AC-8** `docs/art-direction.md` 的 `## §3 构图规范 ⏳（Story 1.7）` 撰写完成。
**至少**包含以下 6 条，每条都要给**可判定或不可判定**的明确标注：

| # | 规范 | 值 | 判定方式 |
|---|---|---|---|
| 3.1 | 画布 | 512 × 512 正方形，`viewBox="0 0 512 512"` | 🤖 机器 |
| 3.2 | 主体占画布比例 | **60% – 75%**（主体外接盒最长边 ÷ 512） | 👁 目视 + 取景框 |
| 3.3 | 统一视角 | **正面偏 3/4 侧，面朝右**；塔与僵尸**共用同一视角** | 👁 目视 |
| 3.4 | 留白 | 主体四边最小留白 **≥ 8% 画布边长（≈41px）** | 🤖 机器（几何外接盒） |
| 3.5 | 重心 | 主体外接框中心落在画布中心 **±6%** 内 | 🤖 机器（几何外接盒） |
| 3.6 | 线宽 | 描边统一 **16px**（512 画布下），三塔一致 | 🤖 机器 |

> **3.2 的区间来源**：`docs/art-direction.md:54-57` 已写明透明底的代价是
> 「同一批词图的**重心**不统一，孩子会先比哪个东西画得大而不是哪个是 dog」，并点名
> 「§3 要规定主体占画布的比例区间（如 60%–75%）」。本 story 把它定死为区间，不是单点。
>
> **3.4 为什么给数字而不是「适当留白」**：塔与僵尸会被缩进 `aspect-ratio: 1/1` 的
> `.battle-cell`（架构 `:471-480`），平板上格子实际边长接近 `--touch-min: 48px`。
> 留白不足时主体会被裁掉边缘，而 6 岁孩子看到的是「植物缺了一块」而不是「留白不够」。
>
> **3.3 为什么是 3/4 侧朝右**（§3 须写进理由）：① **朝向不能自由** —— 僵尸从右向左走、
> 塔向右射击，朝左的塔等于枪口对着自己人；② 3/4 侧比正侧面多一层体积感，
> 比正面对低龄儿童更易辨识；③ 三塔 + 僵尸共用同一视角是**跨图一致性**的前提。
>
> **3.6 为什么是跨塔统一值**：线宽是**颜色以外的第二个一致性维度**。
> 三塔各画各的线宽，缩小到 48px 后描边粗细差会盖过剪影差，AC-5 的兜底又被架空。

**AC-9** §3 必须把规范分成**两张清单**，并在标题处写清楚：

- 🤖 **机器可判定**（AC-16 有守卫）：3.1 / 3.4 / 3.5 / 3.6 + 剪影差异（AC-5）
- 👁 **只能真机目视**（本 story **不能闭合**）：3.2 的主观部分、3.3 的立体感是否成立、
  以及 `docs/art-direction.md:123-125` 移交的**路径/草地 1.59:1 边界复核**

> ⚠️ **诚实性要求**：art-direction §3 原文写着「构图属于**美术判断**，必须与真机上的
> 可辨认性一起试出来，在平板上对着实际尺寸的照片评审比在文档里拍板可靠」。
> ⇒ 本 story 在文档里**写不出**这个判断，也**不允许假装写了**。
> 👁 那几条的状态就是「待 Story 1.10 / 1.19 真机复核」，本 story 到此为止不算闭合。
> **在 §3 里把这件事显式记下来，比让 `[CR]` 发现「§3 声称已定稿但没人看过真机」要好得多。**

### AC 组 3 —— 色板在塔/僵尸上的应用

**AC-11** `src/styles/tokens.css` **新增且只新增一个** token：

```css
--color-asset-stroke: /* 塔与僵尸 SVG 的统一描边色 */;
```

值由你按下列判据**实算**得出（用 `tests/content/palette.test.ts` 里的 WCAG 公式）：

1. 与 `--color-bg`（草地）对比 **≥ 3:1** —— 描边在草地上必须看得见；
2. 与**三个塔底色**各自对比 **≥ 3:1** —— 否则描边糊进塔身，
   AC-5 的剪影差异在 48px 格子上被架空（描边与主体同色时剪影边界消失）；
3. 与 `--color-zombie` 对比 **≥ 3:1** —— 同上。

**算完把实测值连同 L / H 填进 §2 的色值表**（该表已有 L / H 两列），
并在 §2 的「实测对比度」表里加三行实测数字。**不要只写「≥3:1 满足」而不给数字** ——
§2 现有的价值全在那些实测数字上。

⚠️ **色域现实**：三塔底色都在 L 0.058–0.064，描边要同时离草地（0.369）和
三塔都 ≥3:1，**几乎只能落在浅色区**（L ≈ 0.7+）。浅描边 + 深塔身是**符合 AC-5 的**：
它给剪影加了一条与色相无关的高对比边界，正是我们要的兜底。
**不要为了「看起来自然」把描边调暗** —— 那会直接废掉判据 2。

若你判断在当前色域里**做不到**判据 1–3 同时成立：**不要硬凑，停下来报告**，
把三组实测数字贴出来。这是有可能发生的（若成立，处置属设计决策，不是 story 内能拍的）。

这不是「守卫不严」，是**守卫恒等于真**，比没有守卫更坏（它会让人以为守着）。

正确顺序：

```
1. 剥离所有 <!-- ... --> 注释（含跨行）
2. 在剥离后的文本上做属性匹配
3. ⚠️ 若属性值出现在 <title>/<desc>/<metadata> 里，它不是几何规格 —— 匹配范围只取 <svg> 开标签
```

**G5 的签名算法**（照此实现，不要自己发明）：

```
签名 = 剥注释后，
       收集全部绘制元素 <path> <circle> <ellipse> <rect> <polygon> <polyline> <line>
       → 取 (tag, 几何属性) 对：
         path/line/polyline 取 d / x1,y1,x2,y2
         circle 取 cx,cy,r
         ellipse 取 cx,cy,rx,ry
         rect 取 x,y,width,height
         polygon 取 points
       → 剔除 fill / stroke / stroke-width / class / transform / opacity / id
       → 排序后 join
```

**⚠️ G5 有两个已知的假绿写法，一个字都不许用：**

- ❌ **只取元素个数**：`direct.svg` 与 `slow.svg` 若都是 5 个元素，

- ❌ **只比较文件字节**：三个文件因颜色不同而字节必不同 ⇒ 这条断言**任何情况下都通过**，
