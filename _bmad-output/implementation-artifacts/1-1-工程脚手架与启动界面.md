Status: review

## Story

As a 家长,
I want 能在儿子的华为平板浏览器上打开游戏、看到一个开始界面,
So that 我先确认「这东西真的能在他的设备上跑起来」，再谈别的。

## Acceptance Criteria

### AC-1 冷启动可见启动界面

**Given** 一个刚 clone 下来的空仓库
**When** 执行 `npm install && npm run dev`
**Then** 平板浏览器能访问开发服务器，页面显示 StartView：游戏名 + 「开始游戏」按钮
**And** 「开始游戏」按钮是页面上最大、最易点的目标（可点区域 ≥ `--touch-min: 48px`，且为页面唯一的主视觉目标）
**And** 技术栈版本符合架构定案：Vue 3.5.x（不用 3.6 RC）、Vite 8.x、TypeScript `strict: true`、Vitest 5.x（Node ≥ 22.12）

### AC-2 纯逻辑层边界在工具链层成立

**Given** 在 `src/core/` 下写一行 `window.localStorage`
**When** 执行 `npm run build` 或 IDE 类型检查
**Then** 产生编译错误 —— 因为 `tsconfig.core.json` 的 `lib` 不含 `DOM`
**And** 这条边界同时由 ESLint 的 `no-restricted-imports` 保证：`src/core/` import `vue` 报错

### AC-3 目录骨架与 CLI 空壳

**Given** 目录骨架已建立
**When** 检查目录结构
**Then** 符合架构文档的 Project Structure：`src/{core,content,services,app,components,views,styles}/`、`scripts/`、`tests/`、`public/assets/{words,towers,zombies,audio}/`
**And** `scripts/validate-content.ts` 与 `scripts/balance-sim.ts` 已存在且可执行退出码 0（此 story 可为空壳实现）
**And** `src/core/` 内不存在任何 `.test.ts` —— 测试全部在 `tests/`

### AC-4 五个 npm scripts 齐备且此刻可跑

**And** **五个** npm scripts 齐备：`dev` / `build` / `test` / `validate:content` / `balance-sim`
**And** `build` 必须**实际建立**并把类型检查接进去（见 Dev Notes「最容易漏掉的一条」），产出到 `dist/`
**And** `npm run build` 此刻能跑通（产物为空壳应用亦可）
**And** `npm run test` 此刻通过（零测试）

### AC-5 不越界（本 story 明令不做的事）

**And** `src/views/` 下**没有** `UnitSelectView.vue`，且不引入任何选关/单元选择入口（FR59 / OUT-OF-SCOPE-5）
**And** `src/core/` 下**没有**任何业务逻辑文件 —— 只有空的 barrel `index.ts`（逻辑属 Story 1.3）
**And** 没有引入 vue-router / Pinia / Phaser / PixiJS / 任何游戏引擎 / 任何状态管理库 / 任何 JS 补间库
**And** 没有实现音频解锁或 TTS（「开始游戏」按钮的处理器在本 story 中是**空实现 + 明确标注的 TODO**，属 Story 1.2）

### 2. 🔥 极易漏掉的一条：`vite build` 不做类型检查

**AC-2 写的是「执行 `npm run build` 或 IDE 类型检查 → 产生编译错误」。**
但 Vite 8（Rolldown）的构建管线是 **transpile-only** —— 只转译，不做类型检查。已实测确认：
在 `src/core/` 写 `window.localStorage.setItem(...)` 后跑 `vite build`，**构建成功、退出码 0**。
照字面把 `build` 写成 `vite build`，AC-2 直接不成立。

**必须把类型检查接进 build：**

```jsonc
// package.json
{
  "scripts": {
    "dev": "vite",
    "build": "vue-tsc -b --force && vite build",   // 🔒 vue-tsc 与 --force 都不能省
    "preview": "vite preview",
    "test": "vitest run",
    "typecheck": "vue-tsc -b",
    "lint": "eslint .",
    "validate:content": "tsx scripts/validate-content.ts",
    "balance-sim": "tsx scripts/balance-sim.ts"
  }
}
```

- **`vue-tsc -b` 不能省** —— 少了它 build 就没有类型检查，AC-2 报废。
- **`-b` 不能写成 `--noEmit`** —— 已实测：solution 风格的根 `tsconfig.json`（`"files": []` + `references`）
  下 `vue-tsc --noEmit` 是**空转，一个文件都不检查，退出码 0**。
  这是最隐蔽的一种「看起来配了、其实完全没生效」。只有 build 模式 `-b` 才会顺着 references 逐个检查子项目。
- **`--force` 建议加** —— `-b` 依赖 `node_modules/.tmp/*.tsbuildinfo` 做增量，缓存脏了会漏报。
  本地开发无所谓，但 `build` 是后面 Story 1.14（验证调试 UI 不进生产包）与 1.17（部署）依赖的命令，宁可慢也不要漏。

已实测 `src/core/` 引入 `window` 时 `vue-tsc -b` 报 `error TS2304: Cannot find name 'window'.`，退出码 2。

### 3. 🔥 tsconfig 怎么配才能让 IDE 也报错

AC-2 要求「**或 IDE 类型检查**」也产生编译错误。这决定了配置文件怎么摆：

**方案（采用）：solution 风格 + project references**

```
tsconfig.json        ← solution：{ "files": [], "references": [app, core, node] }
tsconfig.app.json    ← 应用代码（含 DOM），exclude src/core
tsconfig.core.json   ← { "lib": ["ES2022"] }，include src/core/**/*   ← 不含 DOM
tsconfig.node.json   ← vite.config.ts / vitest.config.ts / scripts/**
```

VS Code 的 TS Server **支持 project references**：它会顺着根 `tsconfig.json` 的 `references`
把 `src/core/foo.ts` 正确归属到 `tsconfig.core.json`，于是 IDE 里写 `window` 直接标红。

> **反面做法（不要用）：** 只放一个 `tsconfig.json`（含 DOM）再加一个孤立的 `tsconfig.core.json`。
> TS Server 是按目录向上找**字面名为 `tsconfig.json`** 的文件来归属的，根部的 `tsconfig.core.json`
> 它看不见 —— IDE 不报错，只有命令行报错，AC-2 的「或 IDE 类型检查」就落空了。

**三个必须知道的坑（均已在真实项目上实测复现，不是理论推断）：**

1. 🔥 **TS6310：`tsconfig.core.json` 不能写 `noEmit: true`。**
   被 `references` 引用的项目禁止关闭 emit。必须改用
   `"declaration": true` + `"emitDeclarationOnly": true` + `"outDir": "./node_modules/.tmp/core-types"`。
   （注：根项目 `tsconfig.app.json` 用 `composite: true` + `noEmit: true` 是**允许**的，只有被引用的 core 项目不行。）

2. 🔥 **TS6307：`tsconfig.app.json` 即使 `exclude` 了 `src/core`，只要它 `import` 了 core 的文件就会报错。**
   解法：`tsconfig.app.json` 里也必须加 `"references": [{ "path": "./tsconfig.core.json" }]`。
   **这一条 Story 1.1 就要写对** —— 否则本 story 侥幸能过，等 Story 1.3 让 app 层 import core 时才炸。

3. 🔥 **`types: []`（core 与 app 都要写）** —— 不写会全局注入 `@types/node`，
   于是 `core/` 里 `process`、`Buffer` 这些 Node 全局可用，**又漏进来一片本不该有的能力**。
   `tsconfig.node.json` 才写 `"types": ["node"]`。

**已实测跑通的四件套（可直接采用）：**

```jsonc
// tsconfig.json —— solution。files: [] 不可删
{
  "files": [],
  "references": [
    { "path": "./tsconfig.app.json" },
    { "path": "./tsconfig.core.json" },
    { "path": "./tsconfig.node.json" }
  ]
}

// tsconfig.core.json —— 零 DOM 红线就在 lib 这一行
{
  "compilerOptions": {
    "composite": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.core.tsbuildinfo",
    "target": "ES2023",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2023"],                      // ← 没有 DOM，没有 DOM.Iterable
    "types": [],                            // ← 不注入 @types/node
    "strict": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true,
    "declaration": true,                    // ↓ 绕开 TS6310 的必需三件套
    "emitDeclarationOnly": true,
    "outDir": "./node_modules/.tmp/core-types"
  },
  "include": ["src/core/**/*.ts"]
}

// tsconfig.app.json
{
  "compilerOptions": {
    "composite": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.app.tsbuildinfo",
    "target": "ES2023",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2023", "DOM", "DOM.Iterable"],
    "types": [],
    "jsx": "preserve",
    "strict": true,
    "noEmit": true,
    "isolatedModules": true,
    "verbatimModuleSyntax": true,
    "skipLibCheck": true
  },
  "include": ["src/**/*.ts", "src/**/*.vue"],
  "exclude": ["src/core/**/*"],
  "references": [{ "path": "./tsconfig.core.json" }]   // ← 绕开 TS6307，缺了就报错
}

// tsconfig.node.json —— 配置文件自己需要 Node 全局
{
  "compilerOptions": {
    "composite": true,
    "tsBuildInfoFile": "./node_modules/.tmp/tsconfig.node.tsbuildinfo",
    "target": "ES2023",
    "module": "ESNext",
    "moduleResolution": "bundler",
    "lib": ["ES2023"],
    "types": ["node"],
    "strict": true,
    "noEmit": true,
    "isolatedModules": true,
    "skipLibCheck": true
  },
  "include": ["vite.config.ts", "vitest.config.ts"]
}
```

**产物落点：** `.d.ts` 与三个 `.tsbuildinfo` 全在 `node_modules/.tmp/` 下 ——
根 `.gitignore` 已有 `node_modules/` 与 `*.tsbuildinfo`，**无需新增忽略规则**，源码树不会被污染。

**`noUncheckedIndexedAccess` 本 story 明确不开：** 架构只要求 `strict: true`。
该标志会让 `grid[row][col]` 一律变成 `T | undefined`，在 5×9 网格的坐标换算里逼出满屏 `!` ——
那等于把一个本该由 `assert` 承担的不变量问题，降级成了一堆随手写的非空断言。**不变量靠 `core/` 的 assert，不靠类型。**

### 5. 🔥 空目录 git 不跟踪 —— `.gitkeep` 不是可选项

AC-3 要验收目录结构，但 git **不跟踪空目录**。
只 `mkdir` 不放文件，提交后别人 clone 下来 `src/services/`、`public/assets/towers/` 等目录**根本不存在**。

⇒ **每个空目录放一个 `.gitkeep`**（`.gitignore` 未忽略它，会被正常提交）。

同理 `src/core/` 若只有目录没有 `.ts` 文件，`tsconfig.core.json` 的 `include` 会命中 0 个文件，
`vue-tsc -b` 报 **TS18003: No inputs were found** ⇒ 必须建一个空的 `src/core/index.ts`
（它同时就是架构声明的 barrel「唯一对外出口」，不是多余产物）。

> 🔥 **`vue` 必须锁 `~3.5.43`，不能用 `^3.5.0`。**
> `^3.5.0` 的语义是 `>=3.5.0 <4.0.0` —— Vue 3.6 一旦正式发布，`npm install` 就会静默把它拉进来，
> 而架构明确「3.6 不采用」。这是「照文档装、装出了架构禁止的版本」的典型路径。

> 🔥 **`typescript` 必须锁 `~6.0.3`，绝对不能装 `latest`。**
> npm 上 `typescript@latest` 已经是 **7.0.2**（Go 原生重写版），而它**不再导出 `lib/tsc.js`**，

> `ERR_PACKAGE_PATH_NOT_EXPORTED: Package subpath './lib/tsc' is not defined`。
> `typescript-eslint` 的 peer `>=4.8.4 <6.1.0` 也独立确认了同一个上限。
> **已实测：`typescript@6.0.3` + `vue-tsc@3.3.13` + `typescript-eslint@8.71.1` 三者正常。**

**为什么 `scripts/*.ts` 用 `tsx` 而不是 Node 原生 type stripping（已实测）：**
Story 1.4 的 `balance-sim.ts` 要 **import 真实的 `core/` reducer**（AR17 的全部意义所在）。
本机 Node v26.8.2 原生 type stripping 虽已开启，但实测有两个硬伤：

| 工具 | `enum` | import 项目 TS 源码 |
|---|---|---|
| `node scripts/x.ts`（原生） | ❌ `ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX` | ❌ `ERR_MODULE_NOT_FOUND`（不做 `.js`→`.ts` 重写） |
| `tsx` | ✅ | ✅ |
| `vite-node` | ✅ | ✅ |

原生方案会给**整个 `src/core/`** 施加一条与架构无关的书写约束（禁用 enum / namespace / 参数属性），
只为省一个 devDependency，不划算。`vite-node` 与 Vitest 同源、解析规则完全一致，同样可行 ——
**两个都可行，不要同时装。**

**建议 `package.json` 的 `engines`：** `{"node": "^22.12.0 || ^24.0.0 || >=26.0.0"}` ——
对齐 Vitest 5 的真实要求（Node 23 已被排除），比笼统写 `>=22.12` 更诚实。

### 7. ESLint flat config 的写法

```js
// eslint.config.js
import tseslint from 'typescript-eslint'
import vue from 'eslint-plugin-vue'

export default tseslint.config(
  { ignores: ['dist/**', 'node_modules/**', '_bmad/**', '_bmad-output/**', 'docs/**'] },
  ...tseslint.configs.recommended,
  ...vue.configs['flat/recommended'],
  {
    files: ['src/core/**/*.{ts,vue}'],
    rules: {
      'no-restricted-imports': ['error', {
        paths: [
          { name: 'vue', message: 'core/ 是纯逻辑层，零 Vue 依赖（架构 NFR7）。UI 逻辑请放 app/ 或 components/。' },
        ],
        patterns: ['@/app/*', '@/services/*', '@/components/*'],
      }],
      // 纵深防御：tsconfig 已经拦住了，这里再拦一道，防止有人给 tsconfig.core.json 加回 DOM
      'no-restricted-globals': ['error',
        { name: 'window',  message: 'core/ 零 DOM' },
        { name: 'document', message: 'core/ 零 DOM' },
        { name: 'localStorage', message: '存档是 services/save.ts 的职责' },
        { name: 'speechSynthesis', message: 'TTS 是 services/pronunciation.ts 的职责' },
      ],
    },
  },
)
```

> `no-restricted-globals` 是**冗余但值得加**的第二道防线：AC-2 的验收场景是「有人在 core/ 写了 DOM 代码」，
> 单靠 tsconfig 时开发者可能的第一反应是「把 DOM 加回 lib 就好了」。ESLint 会把这条意图明确标红。
>
> 但要清楚各自的分工：**真正的红线是 `tsconfig.core.json` 的 `lib` + `vue-tsc -b`。**
> ESLint 管不住 `globalThis.localStorage` 这类写法，也管不住 `new Function()` 里的字符串。
> 两条防线都要配，但**验收 AC-2 时要看 `vue-tsc -b` 的报错**，那才是判据。

**`index.html` 的 viewport meta（漏了会导致竖屏布局与点击响应都不对）：**

```html

      content="width=device-width, initial-scale=1, maximum-scale=1, viewport-fit=cover" />
```

- `viewport-fit=cover` —— 不写它，`env(safe-area-inset-*)` 恒为 0，架构决策 10 的安全区预留全部落空
- `maximum-scale=1` —— 禁掉双击缩放，否则 Android 上双击有 300ms 延迟，直接击穿 FR78 的 100ms 预算

```css
/* 全局 —— 触控目标的基础行为 */
button, .touch-target {
  touch-action: manipulation;      /* 去掉 300ms tap delay */
  -webkit-tap-highlight-color: transparent;
  min-height: var(--touch-min);    /* 48px */
}
```

### 8b. 🔥 AC-1 的「平板浏览器能访问开发服务器」需要显式开 host

Vite 默认只监听 `localhost`，开发机上 `npm run dev` 能打开，
**平板浏览器输入 `http://<开发机IP>:5173` 会直接连不上** —— 而 AC-1 要求的就是平板能访问。

```ts
// vite.config.ts
import vue from '@vitejs/plugin-vue'
import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [vue()],
  server: {
    host: true,          // ← 监听 0.0.0.0，同 Wi-Fi 的平板才能访问
    allowedHosts: true,  // Vite 的 host header 校验；自用场景放开，避免出现 blocked request 页面
  },
})
```

对应地，`dev` script 可以写成 `vite --host`，与配置文件二选一即可（都写不冲突）。

> ⚠️ 放开 `allowedHosts` 是**自用局域网**场景的合理选择。本项目无后端、无遥测（NFR14 / OUT-OF-SCOPE-9），
> 不存在被外部站点搭便车访问开发服务的面。若将来引入任何需要防跨站请求的机制，此处必须收回。

**验收方式（Task 7.1）：** 平板与开发机连同一个 Wi-Fi，浏览器打开 `http://<开发机IP>:5173`，
确认 StartView 正常渲染。若开发机防火墙未放行，需临时放行 5173 端口。

### 11. Testing Requirements

**本 story 的测试只有一处，但它是这个 story 里最有价值的自动化守卫：**

```
tests/scaffold/core-boundary.test.ts
  ✓ tsconfig.core.json 的 lib 不含 'DOM'，且 types 为空数组
  ✓ tsconfig.app.json 的 exclude 含 src/core，且 references 指向 core
  ✓ eslint 规则对 src/core/** 配了 no-restricted-imports
  ✓ package.json 的 scripts 含 dev / build / test / validate:content / balance-sim，且 build 里含 vue-tsc
  ✓ vitest 配置的 passWithNoTests 为 true
```

理由：AC-2 / AC-3 / AC-4 全部是**「某处配置必须长某个样」**的验收。
纯手工验收意味着 —— 半年后某次重构顺手把 `lib` 里的 `DOM` 加回去，**没有任何东西会报警**；
或者有人把 `build` 里的 `vue-tsc` 删了（反正「build 也能过」），类型检查静默消失。
而边界一旦失效，`core/` 里会悄悄长出 DOM 依赖，直到某天平衡模拟脚本在 Node 里跑不起来才发现。

**这三类「假绿」是这个 story 最真实的失败模式**：配置看起来都在，但没生效。

**不要做的事：**
- 不要为 `StartView.vue` 写组件测试 —— AC-1 的验证方式是在平板上肉眼确认，
  且架构 Testing Strategy 明确「组件测试仅覆盖两处不可由逻辑层覆盖的行为」，
  StartView 不属于这两处。
- 不要在 `src/core/` 放任何 `.test.ts`（NFR16）。
