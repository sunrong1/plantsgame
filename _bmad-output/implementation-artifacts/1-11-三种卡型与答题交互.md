## Story

As a 孩子,
I want 听到一个词或一句话之后,从几个选项里挑出对的那一个,
So that 我在用听力认词、认句、学会怎么回答。

**交付形态警告：** 本 story 是 Epic 1 的**第一个答题交互 story**，
也是**第一个真正消费 30 张词图的 story**。

到今天为止，30 张词图（`public/assets/words/unit-01/`）是**一张都没被渲染过**的资产 ——
Story 1.7/1.8/1.9 只做了「文件存在 + 几何合规 + 构图达标」的守卫，
`src/components/quiz/` 至今只有 `.gitkeep`。

⇒ 这个 AC 背后站着三件从没做过的事：
`src/components/quiz/` 的三个组件、词图 URL 接 `BASE_URL` 的运行时通路、
以及**图片加载失败时不给孩子看破图**的降级通路（NFR13 被标为「压倒性原则」）。

### ⚠️ 裁决的偏离

- **偏离 1 —— 朗读走门面而非 `effects-runner.ts`（对硬约束 4 的张力）**：
  卡面出现时自动朗读是 **FR1 的明确产品要求**，而 1.13 之前没有 effects-runner 可走。
  处置：朗读**只经 `speakQuestion()` 门面**（app 层），组件不直接碰 `pronunciation`；
  ⚠️ **不是**「组件不碰 `services/`」—— `asset-url.ts` 是无状态字符串函数，1.10 已有直接 import 的先例（G25 只禁 `pronunciation`）；
  **绝不 `watch` 状态变化后自行播音效** —— 硬约束 4 真正防的是「同一事件被播多次且无法测试」，
  而卡面朗读的触发源是**「换了一道题」这一可数事件**（`entryId` 变化），
  G27 会断言「连点 3 次重听后 `applyAction` 一次都没被调用、也没有重复触发的自动播放」。
  这条偏离**如实登记在 Completion Notes**，不假装它不存在。
- **偏离 2 —— 组件本地暂存当前题（与 `types.ts:298-300` 那条设计理由有张力）**：
  `types.ts:298-300` 把**为什么两处无限等待必须属于 `State`** 写得很清楚：
  「等选卡与等建造都是**不会自己结束**的状态，若它们只活在组件里，
  **断点续学（决策 5）恢复后无从判断该等什么**，reducer 也无从拒绝非法 action（AC-2）」。
  本 story 正是**让「等选卡」这张卡在组件里多活了一段** —— 从 `applyAnswer` 结束
  （`reducer.ts:195` 切 `awaiting-build`）一直到下一题进入。
  ⇒ **诚实的处置**：暂存的是**两个引用**（`lastQuestion` 指向只读数据、`pickedOptionId` 是瞬时 UI 态），
  **不影响回合流转、不参与 `reduce`、不进 `State`**；FR51（`epics.md:138`「战场状态在局末清空，
  不跨局保留」）靠 1.16 的 `RESTART_LEVEL` 走同一条路径兑现，本 story 不与之冲突。
  ⚠️ **已知代价，且它正是上面那条理由说的那个后果**：**1.15 存档恢复到 `awaiting-build` 时反馈条会消失** ——
  因为组件是空的。**这是正确的**（重启本来就不该停在「刚刚答完」的反馈上，孩子该看到的是「该建塔了」），
  **如实登记，不修**。若未来 1.15 落地后发现反馈是刚需，正确解法是**把 `question` 补进
  `Phase.awaiting-build`**（连同 `assertInvariants`），而不是把组件本地暂存扩大。
- **偏离 3 —— 抢了 `tokens.css:9-11` 标为「Story 1.12」的 `--text-*` 定稿**：
  该处明写「**留空并注释，不要随手填一个值** —— 随手填的值会被后续 story 当成『已定稿』继承，比没有更糟」，
  并附警告 ⚠️。但 1.11 **必须**渲染文字选项（FR13「孩子选择时同时在读」），没有字号就没有这件事。
  处置见 AC-C4：**定稿 `--text-*`**、把归属标记**更正**为 1.11、**并在注释里写出推导算式** ——
  「有据可循的定稿」与「随手填的值」是两回事，前者正是 `tokens.css` 里
  `--space-grid-gap` 那次「归属更正」的同型处理。

- **AC-C5　反馈的载体：组件本地 `lastQuestion`（裁决 4）**
  **Given** `applyAnswer`（`reducer.ts:161-196`）在 `:195` 直接 `return withBuildPhase(next)`，
  而 `Phase.awaiting-build`（`types.ts:309`）是 `{kind, unlocked, sun}` —— **没有 `question`**。

  **Then** 组件持有 `lastQuestion: Ref<Question | null>` + `pickedOptionId: Ref<OptionId | null>`，
  在 `phase.kind === 'awaiting-answer'` 时写入 `phase.question`，在 `awaiting-build` 期间**继续用它渲染**
  **And** ① ⚠️ **写入必须覆盖首次挂载**。Vue 的 `watch` **默认不在 setup 时触发** ——
  只写 `watch(() => phase, ...)` 的话首次渲染 `lastQuestion.value === null`，
  结果是**整个 story 的交付物在浏览器里是空的**，而且
  **T7.6 那次自动朗读（FR1）也永不触发**；组件测试 mount 一个 `awaiting-answer` 的 state
  只会渲染出空 div，G24 / G27 / G28 全红，且红得像是「分派写错了」。
  ⇒ **watch 必须带 `{ immediate: true }`，或改用下面这个 computed 兜底。**
  二选一，后者更不容易漏：
  ```ts
  // 选项 A（推荐）：渲染源永远是「当前 phase 有 question 就用它，否则用上一次的」
  const shown = computed<Question | null>(() =>
    state.value.phase.kind === 'awaiting-answer' ? state.value.phase.question : lastQuestion.value,
  )

  // 选项 B：watch + immediate
  watch(() => state.value.phase, (p) => {
    if (p.kind === 'awaiting-answer') { lastQuestion.value = p.question; pickedOptionId.value = null }
  }, { immediate: true })
  ```
  **And** ② ⚠️ **`lastQuestion === null` 时卡面区不渲染任何东西** —— 不是白框、不是空 div、
  连反馈条也不渲染。**没有题就没有可显示的东西**，而一个空壳 div 会让 G24 的
  「选项区有几个节点」类断言失去参照
  **And** ③ ⚠️ **`pickedOptionId` 与 `lastQuestion` 同一条重置路径，且判据是
  「进入了一道新题」这个事件，不是「`entryId` 变了」**。
  答错 → `END_BUILD` → `resolving` → `round-over` → `CONTINUE` → `nextQuestion`
  （`reducer.ts:100`）**返回同一道题**（AC-4 重考，未 mastered 的仍在题单里），
  此时 `entryId` **不变** ⇒ 只按 `entryId` 监听的 watch 不触发
  ⇒ `pickedOptionId` 仍指着上一轮点过的选项，**孩子还没点，`is-picked` 就已经亮着**。
  ⇒ **每次回到 `awaiting-answer` 都要清 `pickedOptionId`**，不管 `entryId` 变没变
  **And** ④ **为什么 `lastQuestion` 值得存在**：`epics.md:1064` 的「反馈呈现 ≤ 100ms」需要一个
  **可见的载体**。若卡面在 `awaiting-answer` 一结束就卸载，孩子点下去后**屏幕上什么都没发生** ——
  反馈不是「慢了 100ms」，是**根本没有**
  **And** ⑤ `lastQuestion` **不进 `State`、不存档、不参与 `reduce`**；局末由 1.16 的
  `RESTART_LEVEL` 走同一条重置路径清掉（偏离登记见「裁决的偏离」第 2 条）
  **And** ⑥ ⚠️ **`speakQuestion()` 在 `awaiting-build` 期间拿不到 `phase.question`** ——
  它必须先做 phase 收窄（见 AC-D4）。重听在 `awaiting-build` 期间**不提供**
  （卡面上已无待答的题，孩子此时该去建塔）

### 组 D：答题交互与反馈

- **AC-D1　点击 → dispatch → 反馈，组件内零判定**
  **Given** 孩子点一个可点选项
  **When** 提交
  **Then** 组件只做两件事：记下「点了哪个」（组件本地 UI 态）、
  `applyAction(answer(optionId))`（`app/store.ts:104` 是唯一入口）
  **And** **「答对还是答错」不许在组件里算**（NFR8 / 硬约束 2，AI 最容易漂移的一条）
  ⇒ **判定的唯一可行读法是 `state.masteredEntryIds` 里有没有 `question.entryId`：**
  `ANSWER` 之后 reducer 在答对时把 **`question.entryId`** 追加进 `masteredEntryIds`
  （`reducer.ts:192`），答错时原样不动。

  **And** ⚠️⚠️ **绝对不要拿「刚点的那个 `option.id`」去 `includes`。**
  **`option.id` 与 `entryId` 对关键词卡与回应卡根本不是同一个东西**：
  ```
  entryId: u1-s-i-have-a-ball-for-my-dog   (kind: keyword)
    options: u1-ball(correct) / u1-pen / u1-book / u1-chair

  entryId: u1-s-how-are-you                (kind: response)
    options: u1-s-i-am-fine(correct) / u1-s-good-morning / …
  ```
  拿 `option.id` 去查 ⇒ **关键词卡与回应卡的正确率永远显示 0%**。
  而单词卡碰巧能对上（单词卡的正确选项 id 恰好 === entryId），
  所以 **30/37 的卡上「看起来正常」** —— 正是最容易被真浏览器核对放过的形态。
  **And** ⚠️ **不许**在组件里 import 或复制 `isCorrect()`。
  `isCorrect` 属于 reducer 的调用链，组件再调一次就是**第二份判定实现** ——
  两份漂移时没有任何东西会报错（`types.ts:224-227` 的原话）

- **AC-D2　反馈的视觉形态与 token**
  **Given** 答对 / 答错两种结果
  **When** 呈现
  **Then** 用 `--color-correct` / `--color-wrong`（`tokens.css:43-44`，
  1.6 已定稿且被 `tests/content/palette.test.ts` 按 WCAG 实算守着，**一个字都不许改**）
  **And** ⚠️ **三个 class 的来源必须写死成三条公式**，因为 AC-D1 那个判据
  （`masteredEntryIds.includes(entryId)`）**对同一张卡的四个选项是同一个值** ——
  它与「点了哪个选项」无关。写成外层一个 `isRight` 直接绑到四个选项上，
  **答对时四张卡一起变绿**：
  ```
  isPicked = pickedOptionId === option.id
  isRight  = isPicked && masteredEntryIds.includes(lastQuestion.entryId)
  isWrong  = isPicked && !masteredEntryIds.includes(lastQuestion.entryId)
  ```
  ⇒ **`is-right` / `is-wrong` 必须以 `is-picked` 为前提**，这是它们唯一的职责分工：
  「选中且答对」「选中且答错」两个组合，而 `is-picked` 单独存在表示「点过但未判定」
  **And** class 绑定用对象语法**叠加**（`:class="{ 'is-picked': isPicked, 'is-right': isRight, 'is-wrong': isWrong }"`），
  **不是**互斥的 ternary 拼字符串 —— 叠加是合法组合的前提
  **And** ⚠️ **反馈 class 不加 `transition`** —— `tokens.css:118` 的 `--dur-fast` 是 **120ms**，

### 4. 「答对了没」—— 读 reducer 已经算好的事实，不是实现一条规则

组件唯一需要知道的事，来源是 `state`：

```
本题 entryId = u1-s-i-have-a-ball-for-my-dog      ← lastQuestion.entryId
点击 option.id = u1-ball

点击前：state.masteredEntryIds = ['u1-cat']
答对后：applyAction → reducer.ts:192 追加 question.entryId
        → masteredEntryIds = ['u1-cat', 'u1-s-i-have-a-ball-for-my-dog']

组件读：state.masteredEntryIds.includes(lastQuestion.entryId)  →  true  ✅
若误写成 includes('u1-ball')                                    →  false  ❌ 永远显示答错
```

⚠️ 这不是「在组件里实现了一条规则」，它是**读 reducer 已经算好的事实**。
区别在于：前者的值一旦 reducer 改了就会静默错，后者永远跟着 reducer 走。

⚠️ **`entryId` 在 `masteredEntryIds` 里不会有历史污染** ——
`nextQuestion()`（`reducer.ts:100`）跳过已答对的条目，
所以一道题答对后不会再作为当前题出现，`includes` 是精确的答对指示器。

### 5. §5.4 离散度的复现命令

裁决 1 与 AC-F2 引用的「26/30 张卡选项跨度 ≥ 10°」是本次 `[CS]` 实测，
**没有固化成守卫**（§5.4 是目视判据，代理量不是判据）。复现：

```bash
node -e "
const fs=require('fs');
const j=JSON.parse(fs.readFileSync('src/content/units/unit-01.json','utf8'));
const subj=id=>{try{const s=fs.readFileSync('public/assets/words/unit-01/'+id+'.svg','utf8');

⚠️ **口径警告**：`subj()` 取的是文件里**第一个** `rotate(`，是**代理量**。

### 6. 词图加载失败的完整时序

```
OptionCard 渲染 kind==='word' → <img :src="withBaseUrl(o.imageSrc)">
