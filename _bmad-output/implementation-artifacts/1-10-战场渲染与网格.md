## Story

As a 孩子,
I want 看见僵尸从右边一步一步走向我的房子,
So that 我能看见答错的题正在变成后果。

**交付形态警告：** 本 story 是 Epic 1 的**第一个渲染 story**。`src/components/battle/`、
`hud/`、`quiz/`、`debug/` 四个目录到今天为止全是 0 字节 `.gitkeep`，全项目只有
**2 个 `.vue` 文件**（`src/App.vue` 15 行、`src/views/StartView.vue` 107 行），
**没有 store、没有组件、没有组件测试**。

⇒ 「战场渲染」这个 AC 背后还站着三件从没做过的事：`src/app/store.ts`、组件层的
第一条数据通路、以及整个组件测试环境。三者任一漏掉，这个 story 就只是画了个好看的框。

### ⚠️ 裁决的偏离

- **裁决 2 偏离 AC「不新增任何依赖」**：Story 1.7 的 AC-7 明写「不新增任何依赖」，
  本 story 要加 `jsdom`（devDependency）。**这是 `epics.md` 与 story 级 AC 的显式偏离**，
  如实登记在此。替代方案（不装、组件只导出纯函数）会放弃架构 `:930-931` 要求的
  「组件测试：射程预览形状渲染 / 阶段切换 UI 表现」，而后者正是 1.12 要用的。
- **裁决 3 与内容数据的边界**：**只有塔 / 僵尸搬进 `src/` 并接 base。**
  `WORD_IMAGE_URL_PREFIX`（`validate-content.ts:73`）与 `expectedImageUrl()`（`:123`）
  **一个字都不许动** —— 那是**内容 JSON 里存的值的判据**（`unit-01.json` 里 30 张词图的
  `imageSrc` 全部是无 base 的 `/assets/words/unit-01/u1-dog.svg`），JSON 存什么就校验什么。
  词图的 base 由谁负责，见 §Dev Notes 13。
- **`[CR]` 2026-10-16 新增：AC-11 的「组件只认识 `app/`，不直接 import `services/`」——
  `Tower.vue` / `Zombie.vue` 破了这条，实测成立。** 两条规则同时被违反：
  AC-11 逐字写着「**组件只认识 `app/`，不直接 import `services/`**」，
  而 AC-4 又**逐字要求**这两个组件用 `src/services/asset-url.ts` 拼 `<img src>` ——
  **两条 AC 物理上不可兼得。** 架构硬约束 8（R-08）的依赖方向
  `components/ → app/ → services/ → core/` 同样被跨过。

  **用户裁决（AskUserQuestion，2026-10-16）：改登记，不改代码。** 理由：
  - `asset-url.ts` 是**纯字符串函数**，无副作用、无顺序不变量、无模块级可变状态 ——
    它不承载任何「顺序」语义，跨层调用它不会绕过 `effects-runner` 那条硬约束；
  - 为它加一个 `app/` 门面（转发一层）**自身也要 import `services/`**，
    只是把同一次跨层挪远一格，还多一个文件、多一份要维护的转发；
  - 真正的风险在**将来**：新组件会照抄这个先例而不重新论证。所以本条登记进
    **Dev Notes 的边界表**（`⚠️ 本层例外，不是通例`），让下一个写组件的人
    **看得见**这个例外存在，而不是从 `Tower.vue` 里无声继承它。

  ⇒ **代码一行未改**；本 story 保留 `Tower.vue` / `Zombie.vue` 的既有写法
  （文件头已逐字写明理由），本条**只登记**。**AC-11 未删除、未降级。**

### 2. 组件写法范式（照 `StartView.vue`，它是全项目唯一有样式的组件）

| 方面 | 做法 |
|---|---|
| SFC 结构 | `<script setup lang="ts">` → `<template>` → `<style scoped>`，**三段固定顺序** |
| script 顶部 | **必有一大段块注释**：职责边界 + **刻意不做的事** + 引用的 FR/AC/架构行号 |
| import 路径 | **相对路径，无 `@/` 别名**（`eslint.config.js:62-66` 明说项目无 alias） |
| 依赖方向 | 组件只认识 `app/`（`StartView.vue:14-17`：直接 import `../services/pronunciation` 是跳过 app/ 的违规导入） |
| 事件处理 | `function onX(): void` 显式返回类型；**不用 async** |
| class 绑定 | `:class="{ 'is-active': ... }"` 对象语法，便于叠加（1.12 的射程覆盖层要叠加） |
| CSS 变量 | 一律 `var(--xxx)` |
| 动效 | `transition: xxx var(--dur-fast) ease-out` —— **时长只出现在 CSS** |
| style 内注释 | 每个声明块上方必有中文注释写明依据（FR 号 / 为什么这么取值） |

⚠️ **`script setup` 漏 import 组件 = vue-tsc / build / test / lint 全绿但页面白屏。**
`App.vue:6-8` 与 `eslint.config.js:44-48`（`vue/no-undef-components: 'error'`）都为此写了注释。

### 🔴 P0：ESLint 边界守卫的**查询模型**是假绿 —— 换成 ESLint 自己的解析器

三层里只有一层抓到，而且是最严重的一条：**Story 1.10 引以为傲的 AC-14 机器守卫（G15）
连同 `core-boundary.test.ts` / `audio-unlock-guard.test.ts` / `content-boundary.test.ts`
三条边界守卫，在本 story 写完之前一直是「看着在守、实际没守」**。

原实现长这样（`tests/fixtures/eslint-rules.ts` 的前身，以及**另外三份各自抄的副本**）：

```ts
const blocks = eslintConfig.filter(
  (b) => !b.files || (Array.isArray(b.files) ? b.files : [b.files]).includes(fileGlob),
)
```

**洞一：它问的是「哪个块的名字等于这个 glob」，不是「哪个块真的命中这个文件」。**
实测：在 `eslint.config.js` 末尾追加一个 `files` 只写 `src/components/battle/` 子树
（比本 story 的块**更窄**）、带 `rules: { 'no-restricted-imports': 'off' }` 的配置块 ——
`npx eslint --print-config` 显示 `Tower.vue` 的该规则严重级别是 **0（off）**，
而 **G15 的 38 条断言全绿**，`eslint .` exit 0。因为那个更窄的 glob 覆盖了本 story 的
**全部**组件，而 `includes('src/components/' + 那个 glob)` 为 false ⇒ 那个块被整个漏掉。
⇒ 组件层「不得直读战斗数值」的守卫可以被一行配置完全停掉而无人知情。
**更糟的是原注释白纸黑字写着「追加一个 off 的块本函数会如实返回 'off'」——
这句话只在追加块复用同一个 glob 字符串时成立。注释比代码更自信，是最坏的一种。**

**洞二：它完全不看 `ignores`。** flat config 的 `ignores` 是**全局排除**，命中后 ESLint
连 lint 都不做，而 lint 脚本是 `eslint .`（无 `--max-warnings`）⇒ 被 ignore 的文件**静默跳过**。
实测把 `'src/components/**'` 加进 `ignores`：受 lint 文件数 **58 → 55**，
`vue/no-undef-components`（「漏 import 组件 → 白屏」那条 Debug Log #4 的守卫）同时失效，
**而全部守卫照绿**。

**修法（不是打补丁，是换掉模型）**：改用 `ESLint#calculateConfigForFile(path)` ——
它返回的**就是那个文件的最终生效配置**（已含 glob 匹配顺序与 `ignores` 排除）。
洞一（窄 glob 的覆盖顺序）与洞二（ignores）**由构造性保证同时消失**，不再依赖我手写 glob 语义。

| | 修前 | 修后 |
|---|---|---|
| 查询实现份数 | **4 份**（`eslint-rules.ts` + `core-boundary` + `audio-unlock-guard` + `content-boundary`，各抄一份 `rulesFor`） | **1 份** |
| 更窄 glob + `'off'`（M51） | 0 红 | **1 红** |
| `'src/components/**'` 进 ignores（M52） | 0 红 | **4 红** |

顺带修掉的三个连带问题：
- `calculateConfigForFile` 返回的是**归一化**配置，严重级别是**数字** `0/1/2` 而不是
  `'off'/'warn'/'error'` ⇒ 新增 `severityOf()` 在**一处**做映射，不让每个调用方各写一遍。
- 被全局 ignore 的文件它返回 **`undefined` 而不是空配置** ⇒ 直接读 `config.rules` 会抛
  `TypeError`，把「守卫正确地发现文件被忽略」降级成「测试崩了」。改为 `config?.rules ?? {}`，
  并新增 `isGloballyIgnored()` + 一条「每个探针文件都没被 ignores 排除」的断言。
- 探针文件必须**真实存在**（`calculateConfigForFile` 对不存在的文件按最接近的 glob 兜底）
  ⇒ 新增 `probeFilesExist()`。**旧实现这份探针名单只有 8 个文件，漏了
  `src/services/audio.ts` 与 `src/app/audio-unlock.ts`** —— 补上后 `audio-unlock-guard` 的
