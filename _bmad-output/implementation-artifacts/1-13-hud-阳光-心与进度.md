# Story 1.13: HUD：阳光、心与进度

Status: ready-for-dev

## Story

As a 孩子,
I want 随时看得见自己有多少阳光、还剩几颗心、读到哪了,
so that 我知道自己还剩多少机会。

### 裁决 2 —— 掉心动画走「状态 → class → CSS 过渡」，**不进 effects-runner**；判据落在 `core/hud.ts`，1.14 的掉心音效必须复用同一份

**冲突事实：**

| 来源 | 原文 |
|---|---|
| `game-architecture.md:1031`（硬约束表） | 「\| 副作用只在 `effects-runner.ts` 执行 \| 组件内 `watch` 后自行播音效会导致重复播放且不可测 \|」 |
| `epics.md:1181` | `runEffects` 的返回列表含「音效 / **动效** / TTS / 存档」⇒ 动效也归 effects-runner |
| `game-architecture.md:459-461`（§9 动效规范） | 「**方案：CSS transition + Vue `<Transition>`，禁止引入 JS 补间库。**」「**范式：「状态变化 → 切换 class → CSS 过渡」**」 |
| `game-architecture.md:463` | 「本作动效均为离散事件反馈（答对上扬、答错下行、**掉心碎裂**…），不需要时间轴编排或缓动函数库」 |
| `src/components/battle/RangeOverlay.vue` + `BattleField.vue` 的 `refusedKey` | **1.12 已经这么做了** —— 组件内 Vue `ref` → class → CSS `@keyframes`，不经任何 effects-runner |

**裁决：**
1. 掉心动画 = **state 的表现**，不是副作用。由 `HeartRow` 内部一个 Vue `ref` 表达「刚刚掉了心」，切 class，动画时长写 CSS。
   先例是 1.12 的 `.is-refused`（`RangeOverlay.vue` 的 `VARIANT_CLASS` 映射 + `.is-refused { animation: … }`，由 `BattleField.vue` 的 `refusedKey` 驱动），不是本 story 新开的口子。
2. **判据不放组件里。** 「本帧新耗尽的是哪几个心槽」由 `core/hud.ts` 的纯函数 `lostSlotIndexes(prev, next)` 给出（AC-B7）。
   ⚠️ 这样 1.14 实现掉心音效时**必须调同一个判据**（取 `.length`）—— 否则画面与声音会各判一次，
   两份判据迟早分叉，而「同一事实两个来源」正是本仓库反复抓的漂移形态
   （1.10 的 `grid.ts:184-185`、1.12 把 reducer 两条硬编码塔位判断收口到 `grid.ts` 的 `buildBlockedReason`）。
3. 本 story **不做**音效。1.14 接上时，掉心音效与掉心动画共用 `lostSlotIndexes`。

### 裁决 3 —— 进度数据源：引入**内存态** `progress`，形状逐字锁死为架构决策 5 的定义；1.15 只加序列化

**冲突事实：**

| 来源 | 原文 |
|---|---|
| `epics.md:1153` | 「`ProgressBar` 显示「第 N 单元 · x/y」，其中 y = 该单元待答题总数」 |
| `game-architecture.md:354` | 「- 进度条读 `progress`」—— 而 `progress` 住在 `SaveFile` 里（`:342-345`） |
| `src/app/store.ts:15` | 「· **不做存档** —— 属 Story 1.15（决策 5 的 `SaveFile`）」 |
| 全仓 grep | `SaveFile` / `masteredWordIds` / `currentUnitIndex` 在 `src/` 里**零实现**（只有 `src/content/index.ts:12` 与 `tests/content/unit-01.test.ts:388` 两句注释提到 `currentUnitIndex`） |

**⚠️ 为什么不能用本局口径糊过去：** 若 ProgressBar 读 `masteredEntryIds.length / deck.length`，
一局约 10 题（`epics.md:138`「一局 = 一场独立战斗（约 10 题 = 10 回合）」）、单元 1 有 37 词
⇒ 一局最多答对 10 个；局末战场清空（FR51，`epics.md:138`）时这个数**归零**，
「第 1 单元 · 9/37」在两局之间读起来像**退了 5 个词** —— 直接违反 FR58「进度只增不减」与
FR60「进度与对局是两套独立持久化」。
`game-architecture.md:350-357` 把这条写得很重：「若把进度字段混进 `GameState`，局末清空战场时会把「21/60」一起清掉」。

**裁决：**
1. 本 story 在 `src/app/store.ts` 引入模块级 `const progress = ref<Progress>({ currentUnitIndex: 0, masteredWordIds: [] })`，
   **键名逐字等于** `game-architecture.md:342-345`（`currentUnitIndex` / `masteredWordIds`）。
   守卫 **G50** 断言键名 —— 1.13 改名会让 1.15 背一次迁移。
2. **只读不写 `currentUnitIndex`**：单元推进归 1.16（FR52 / FR59）。本 story 初值 0。
3. `masteredWordIds` 只增不减，由 `core/hud.ts` 的 `advanceProgress(progress, next)` 从 `State` 增量派生（AC-B3）。
4. 本 story **不写 localStorage**、不 import `services/save.ts`（它还不存在）。
5. ⚠️ 这是本 story 唯一一处「提前引入 1.15 的类型」。属**形状锁定**而非依赖倒置：
   1.15 拿到的是已经正确的形状，只加读 / 写 / `schemaVersion` 校验。

**「第 N 单元」显示哪个 N：** 用 `state.unitNumber`（`src/core/types.ts:324`，唯一事实源；
`src/app/store.ts:48` 写死 `FIRST_UNIT_NUMBER = 1`，因无选关自由），
**不用** `progress.currentUnitIndex + 1` —— 后者本 story 不写，写了就多一个会与 `unitNumber` 失同步的第二来源。

### 裁决 4 —— **不引入** `sunEarned`（累计阳光字段）；「累计所得只增不减」如实降级为**负向守卫**

**冲突事实：** `epics.md:1158` 要求「余额可增可减；**累计所得只增不减**，二者不得混为一谈」，
`epics.md:1164` 同时要求「HUD 不展示「阳光总数」这类学习分数」。
而 `State` 只有 `sun: number`（`src/core/types.ts:330-331`，注释逐字：「阳光**余额**，唯一可写事实源」），
全仓 grep `sunEarned` **零命中**。

**裁决：不加字段。**
理由：FR66 / `gdd.md:380`「**阳光不出现在学习评价中**。没有「阳光总数」这一分数，不比较不同单元的阳光存量」
⇒ v1.0 里累计值**没有任何产品消费者**。为一个永不渲染、永不被任何逻辑读取的值建字段，
正是 `src/app/store.ts:152-159` 那段注释自己点名批评的形态（它拒绝为 `runEffects` 写空函数占位，
理由是「空函数会让 `applyAction` 的调用点看起来『已经接上副作用链路』，而实际上一个音效都没播过」）。
死字段的代价与空占位函数同型，只是更隐蔽 —— 它连函数都不给你一个能观察的调用点。

**「不得混为一谈」怎么守：** 转成**可证伪的负向判据**（AC-E1 / 守卫 G49a / G48）：
HUD 组件与其测试的源码里**不得出现**任何第二来源标识符
（`sunEarned` / `totalEarned` / `sunTotal` / `累计`），且 `SunCounter` 的可见文本 **恒等于** `String(state.sun)`。
即：混为一谈在这里等价于「出现了第二个数字」，守卫直接打在「出现」上。

**恢复条件**（写进 `deferred-work.md`）：若将来出现跨局阳光统计的产品需求（当前 FR66 明令不要），
再引入字段并同时改守卫。

### 裁决 7 —— `core/hud.ts` 内持有一份 entryId 前缀形态知识，并登记为偏离

**冲突事实：** `progressDisplay` 要算「`masteredWordIds` 中属于本单元的条目数」，
而「属于本单元」的唯一现成实现是 `src/content/schema.ts` 的 `unitPrefix(unitNumber)` 与
`ENTRY_ID_PATTERN`（`schema.ts:42/106`）。但 **`core/` 不得 import `content/`**。

**裁决：** `core/hud.ts` 用 `id.startsWith('u' + unitNumber + '-')` 判定，
即**在 `core/` 内持有 entryId 前缀形态的第二份知识**，登记为偏离 #7。
形态依据是 `game-architecture.md:375`（id 带单元前缀，`u1-dog` / `u2-apple`）。

⚠️ 这是取舍，**不是**有工具强制的硬约束：`eslint.config.js` 的 `src/core/**` 块只禁
`vue` / `app` / `services`，**没有禁 `content`**。理由是 `src/content/index.ts:37` 是 `RAW_UNITS` 的静态
import JSON，让 `core/` 依赖它会把 37 条词条拖进每一个 core 测试。
⚠️ **别去找一条不存在的守卫** —— 若将来 `content/` 与 `core/` 的 id 形态分叉，
`tests/content/` 那侧有 schema 守卫，`core/hud.ts` 这侧没有 ⇒ 分叉会静默通过。

### 3. API 契约（签名已定，实现自由）

```ts
// src/core/hud.ts
export interface Progress {
  readonly currentUnitIndex: number
  readonly masteredWordIds: readonly string[]
}

/** 两帧之间实际掉了几颗心。恒 ∈ [0, HEARTS]。不持有余额。 */
export function heartsLostBetween(prev: State, next: State): number

/** 心槽位：长度 === HEARTS，第 i 位 = i < state.hearts（左低右高）。 */
export function heartSlots(state: State): readonly boolean[]

/** 本帧新耗尽的心槽下标（一次掉 2 心 ⇒ 两个下标）。空数组 = 没掉。 */
export function lostSlotIndexes(prev: State, next: State): readonly number[]

/** 并进跨局进度。幂等、只增不减、不改入参；无增量时返回入参本身。 */
export function advanceProgress(progress: Progress, next: State): Progress

/** 「第 N 单元 · x/y」与进度条比例。unitTotal 由调用方传入。 */
export function progressDisplay(
  progress: Progress,
  unitNumber: number,
  unitTotal: number,
): {
  readonly unitNumber: number
  readonly mastered: number
  readonly total: number
  readonly ratio: number
}
```

### 7. 已知的历史坑（对本 story 强适用）

1. **判据先在真实文本上试一遍。** 1.12 的 M56 实测 0 红：判据 `/\bthrow\s/` 在中文顿号前不匹配
   ⇒ 自测**因为错误的原因而绿**。中文标点击穿 `\s` / `\b`（1.5）。
2. **构造上恒真的断言 = 假绿。** 1.10 Debug Log #3。AC-F5 点了本 story 的**四处**高危位置。
3. **计数守卫必须 `flush: 'sync'`。** 1.12 实测 `'pre'` 把同 tick 的多次同步赋值合并成一次。
4. **心数一律读 `state.hearts`；掉心量一律用夹后差值**（`heartsLostBetween` / `lostSlotIndexes`），
   **不用** `resolveCombatRound().heartsLost` —— `deferred-work.md:381-393` 已登记它会误记，
   而那条的「已修」是给计数场景（level-driver / balance-sim）的，**不是给 HUD 的**。
5. **漏 import 组件 = 白屏且全绿。** `vue/no-undef-components: 'error'` 守着，但 vitest 不跑 lint
   ⇒ 每加一个 `.vue` 都要跑 `npm run typecheck`。
6. **vitest 不做类型检查。** 1.9 实测：`Set<CompositionTier | 'null'>` 把真·空值写成字符串，
   vitest 765 全绿而 `typecheck` 红。
7. **实测值优先于文档值。** 1.5。AC-G1 的量若与推断不符，改代码或改记录，**不要改判据**。
8. **按位置键入会覆盖吞实体。** 测试里找元素用 `[data-*]` 或 class，**不用 `nth-child`**
   （1.12 的 `directChildClasses()` 反向夹具就是这么写的）。
9. **现有 token 的值一个都不许改。** 1.12 实测约束；`palette.test.ts` 按 WCAG 实算守着。
10. **`as` 会让「编译期断言」在类型改坏时失灵。** 守卫里别用 `as` 硬转。
11. **「守卫写不出来」时别硬写。** `deferred-work.md:389-393` 记着一条「20000 个种子一次都没触发、
    写一个永远为绿的守卫比不写更坏」的判例 —— 本 story 的 G44 之所以能写，正是因为它**合成 State、
    不经战斗流程**。
