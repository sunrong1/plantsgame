## §0 裁决 —— 开工前已定，Dev 不必重新决定

### 裁决 1 —— 🔥 `[core] turn N …` 日志**不能写在 `src/core/` 里**

`epics.md` 的 AC 逐字要一条带 `[core]` 前缀的每回合日志。而 `docs/rules/architecture.md`
的 R-14 守卫（`tests/scaffold/save-boundary.test.ts`）对 `src/core/**` **逐文件断言零 `console.`**
（`readdirSync` 扫整层，匹配前先 `stripComments`）。

两条都是硬的 ⇒ **日志的「前缀」是语义标签，不是「谁写的」**。

**落法（三层各司其职，与既有的 `SFX` 完全同型）：**

```ts
// ① core/effects.ts —— 新增第 5 个 Effect 成员，纯函数产出那一行文本
export type Effect =
  | { readonly kind: 'SFX'; readonly cue: SfxCue }
  | { readonly kind: 'ANIMATION'; readonly name: string }
  | { readonly kind: 'TTS'; readonly text: string; readonly entryId: string }
  | { readonly kind: 'SAVE'; readonly currentGame: State | null }
  | { readonly kind: 'TRACE'; readonly line: string }   // 🆕 1.17

// ② app/effects-runner.ts —— 唯一执行副作用的地方（R-04），DEV 门控只在这一处
case 'TRACE':
  if (import.meta.env.DEV) console.info(effect.line)
  break

// ③ core/actions.ts —— actionName() 早就在，注释逐字说它是给这条日志用的
```

⚠️ **为什么不用「core 导出一个 `turnLogLine()` 纯函数，runner 直接调」** ——
那样判据就散在 runner 里，而 `runEffects` 就不再是「待执行副作用的唯一产生处」。
加成员的好处是：**`assertNeverEffect` 会逼你在 `runner` 的 `switch` 里补分支**（漏了当场 typecheck 红），
而且「每回合一条」这条判据**留在 `core/` 里可测**（AR8：副作用触发逻辑本身可被测试）。

⚠️ **`Effect` 联合加成员 ⇒ `assertNeverEffect` 与所有穷尽 `switch` 必须同步**。
TypeScript 会替你做这件事（这正是它的用处），**不要用 `as` 绕过去**（R-51 第 2 类）。

⚠️ **`TRACE` 不是 `DEBUG` 级别的日志**。裁决 2 单独说。

### 裁决 2 —— 🔥 回合日志按 **INFO + DEV 门控**，这是对 NFR14 的一处解释，须留痕

`epics.md` 的 AC 逐字把两件事写在一起：「每回合记录一条日志」与
「`DEBUG` 级日志经 `import.meta.env.DEV` 门控，生产构建中不输出」。
`game-architecture.md` 的 Logging 表把「回合转换」归在 **INFO**。

两者字面上打架。**裁决：回合日志是 INFO 级，但同样经 `import.meta.env.DEV` 门控。**

理由：门控的条件不是「级别」，是**「这条日志对生产环境的用户有没有价值」**。
回合流水对家长零价值、对生产包是纯噪音（每 20 秒一行，永远挂在 console 里）。

⚠️ **必须在 `effects.ts` 的注释里逐字写下这个理由**，否则下一个人会按 Logging 表
把门控删掉（表里 INFO 没有门控要求）。R-41：引入边界约束要么给守卫要么明确记。守卫 **G105**。

### 裁决 3 —— 会话录制点是 `applyAction`，录制器住在 `app/`

`src/app/store.ts` 的 `applyAction` 是**唯一**能同时看见 `action` / `prev` / `next` 的地方
（AR7 / 架构边界第 4 条）。⇒ 录制器挂在那里。

```ts
// 新模块 src/app/session-recorder.ts（app 层，不是 core 层 —— 它要 console）
export interface SessionExport {
  readonly initialState: State
  readonly actions: readonly Action[]
}
export function recordStep(action: Action, prev: State, next: State): void
export function exportSession(): SessionExport
export function resetSession(): void
export function isRecording(): boolean
```

⚠️ **`initialState` 是「第一条 action **之前**的 `prev`」**，不是 `createInitialState()` 的重算结果。
守卫 **G97** 专打这一条。

⚠️ **录制常开，导出按需**。AC 逐字要求「每回合记录一条」，那不是开关；
**导出**才是面板上的一个按钮。代价是每回合 push 一个引用 —— `State` 全是 `readonly`
的普通对象，push 引用**不产生深拷贝**，O(1)。

⚠️ **`State` 里的 `deck` 是整局的题单全集**（逐字「一局内数组本身永不变动」），
所以 `initialState` 快照自带全部内容 ⇒ **导出的 JSON 自足**，不依赖内容层版本。
这正是「复现 = 把该 JSON 喂进 reducer」能成立的原因。

### 裁决 5 —— 🔥 调试开关：**dev-only 状态补偿缝**，`core/` 一个字不改

「无限心 / 无限阳光 / 直接通关」**在当前架构下无法用既有 `Action` 实现**：

| 开关 | 字面可实现？ | 实测原因 |
|---|---|---|
| 无限心 | ❌ | `core/reducer.ts` 的 `assertCounters` 逐字 `hearts > HEARTS` 即抛错，**心数越界是硬失败** |
| 无限阳光 | ✅ | `assertCounters` 对 `sun` 只查 `>= 0`，**没有上界** |
| 直接通关 | ✅ | 把 `masteredEntryIds` 补满后走**真** `CONTINUE`，`nextQuestion` 返回 `null` ⇒ `reduce` **真实产出** `level-complete` |

⇒ **不新增 `DEBUG_*` Action 变体、不改 `core/`、不改 `balance.ts`**
（R-20：心数上限是产品决策，改动前必须问人）。
落法是在 `store.applyAction` 的 `reduce` 之后加**一条**仅 DEV 生效的补偿：

```ts
const reduced = reduce(prev, action)
// 🆕 1.17 裁决 5：dev-only 补偿缝。
// 仅 import.meta.env.DEV 为真时存在，生产构建整段被 Vite 的静态替换 tree-shake。
const next = import.meta.env.DEV ? devAdjust(reduced, devFlags) : reduced
```

**`devAdjust` 的三条判据（缺一不可）：**

1. **`hearts → Math.max(1, hearts)`** —— 夹在 **1** 而不是「无限」。
   ⚠️ 心数必须**始终落在 `[0, HEARTS]`**，否则 `assertInvariants` 会抛
   （`applyAction` 每次 dispatch 都会过它）⇒ 「无限心」的真实语义是
   **「掉心后立刻回到 1，永远不会耗尽」**，不是「心数变成 ∞」。
   ⚠️ **这条要在面板 UI 上如实写出来**，不要标成「∞」—— 家长按字面理解会以为可以故意耗心。
2. **`sun → Math.max(sun, 9999)`** —— 只抬不降，恒满足 `>= 0`。
3. **`masteredEntryIds → 补满 `deck`**（仅「直接通关」开启时）。
   ⚠️ **补满之后必须让玩家再走一次**由 `reduce` 判定的 `CONTINUE`，
   **不许在 `devAdjust` 里直接造一个 `phase.kind === 'level-complete'` 的 state**
   —— 那样 `level-complete` 就不是 `reduce` 的产物，
   而 1.16 的 G87–G96 与 1.5 的整组 reducer 守卫全都失去了意义（R-41）。

⚠️ **补偿缝排在 `runEffectsFromStore` 之前**，否则 `SAVE` effect 携带的是 `reduced`
（`hearts = 0`）而内存里是 `1` ⇒ **盘上与内存不一致**，
正是 R-06 段记的那个「断言的观察点决定了它能看见哪一种滞后」的最贵漏网形态。
守卫 **G109** 专打这条。

⚠️ **`devAdjust` 的输出不再过 `assertInvariants`**（它在 `reduce` 的出口，不在补偿之后）。
三条判据都在合法区间内是这条设计的前提 ⇒ **必须在注释里写明，
并加一条守卫断言补偿后仍能过 `assertInvariants`**（**G108**）。

⚠️ **缝插在 `reduce` 之后、`nextProgress` 计算之前还是之后，要自己判断一次**：
判据是「`SAVE` 写出去的那份必须与内存里孩子看到的一致」⇒ 两处都应看到补偿后的值。

### 组 B —— 会话录制与回放（本 story 的核心）

**AC-B1** 新模块 `src/app/session-recorder.ts`，导出裁决 3 列出的五个成员。
三条判据全都要：

1. **`initialState` 是第一条 action 的 `prev`**，不是 `createInitialState()` 的重算。
2. **`actions` 的顺序就是 dispatch 顺序**，一条不漏、一条不多。
3. **`next` 收下但当前不导出** —— 留参数是为了让未来的「步进回放」不必改签名，
   **并用一条断言说明它现在不参与导出**（否则它是一个骗人的参数）。

守卫 **G97**（判据 1）、**G98**（判据 2 + 3）。

**AC-B2** 🔥 **回放是纯函数，放 `src/core/`**（放 `core/` 是因为它零 DOM 零 Vue，
与「复现 = 喂进 reducer」这句话的性质完全一致）：

```ts
export function replaySession(session: {
  initialState: State
  actions: readonly Action[]
}): State
```

⚠️ **`SessionExport` 定义在 `app/`，`core/` 不得 import `app/`**（R-08 + ESLint 硬禁）。
⇒ `core/` 侧只接受**结构相同**的入参，在 `core/` 里用 `import type { State, Action }`
从 barrel 声明本地类型。
**两份类型定义不是 R-37 的复制** —— 一个是「要导出的文件格式」，一个是「回放的入参形状」，
`core/` 那份逐字写上「与 `app/session-recorder` 的 `SessionExport` 结构相同，
刻意不共享类型以免 `core/` 依赖 `app/`」。

⚠️ **回放的判据只有一条：喂进 `reduce`，得到终态。** 不许跑 effects、不许写盘、不许播音效。
守卫 **G99**：同一份 JSON 喂两次，终态 `JSON.stringify` 逐字相等。

**AC-B3** 🔥 **回放必须验「终态逐字还原」**，且这条 AC 要落在**真的 JSON 往返**上：

```
exportSession() → JSON.stringify → JSON.parse → replaySession() → 与原 state 逐字相等
```

⚠️ **中间那一步 `JSON.parse` 不能省** —— 省掉它就验不到「`State` 里有循环引用 /
有 `undefined` 键 / 有 `Map`」，而那正是「导出后打不开」的根因。
守卫 **G100**（`exportSession()` 的结果必须 `JSON.parse` 成功且回放后逐字相等）。

**AC-B4** ⚠️ **录制器不得对 state 做任何深拷贝或冻结**。
`State` 全是 `readonly` 的普通对象（`types.ts` 的注释逐字解释了 `grid` 为什么是
`Record` 而不是 `Map` —— 就是为了可序列化）⇒ **push 引用即可**。
⚠️ 反过来：**如果哪天有人给 `State` 加了循环引用**，`G100` 会立刻红 —— 这正是它的价值。

**AC-B5** ⚠️ **`resetSession()` 挂在 `RESTART_LEVEL` 上**（判据是 `action.type`，
不是相位）。理由与 1.16 裁决 4(b) 同型：重打后盘上/内存里的仍是上一局，
而会话录制的 `initialState` 也必须是**新一局**的起点。
守卫 **G101**（重打后 `exportSession().initialState.turn === 1`）。

**AC-B6** 回放校验落 `tests/core/session-replay.test.ts`（裁决 4），
**不许写进 `scripts/`**（R-61）。
⚠️ 这条用例必须**至少含一段真实长度的会话**（≥ 3 回合、含一次答错触发重考），
否则验的是「一局的碎片」不是「一局」。

### 组 C —— 每回合那条 `[core] turn N …` 日志

**AC-C1** AC 逐字要求的格式，一个字段都不许少：

```
[core] turn N  action=<T>  sun=<n>  hearts=<n>  zombies=<n>
```

⚠️ **字段之间是两个空格** —— AC 逐字如此。守卫 **G102** 用**精确字符串**比对，
不许只断言「包含 `turn`」（那是一条恒绿的装饰守卫，R-51）。

**AC-C2** `<T>` **必须取自 `actionName()`**，不许自己另写一张映射表。
⚠️ `actionName` 逐字会在联合外的类型上**抛错**而不是返回 `'unknown'` ——
它的注释逐字说这是刻意的（「对局日志里出现一条无法归因的记录」是最该看见的一行）。
守卫 **G103**：`actionName` 的返回值与日志里的 `<T>` 逐字相等。

**AC-C3** 🔥 **`sun` / `hearts` / `zombies` 取自哪一侧：`prev` 还是 `next`？**

⚠️ AC 没说。这是**真问题**：日志的用途是「复现出不对劲的那一瞬」，
**那一瞬是 dispatch 之后的状态** ⇒ **取 `next`**。

⚠️ **但整回合有 4~6 次 dispatch**（`ANSWER` → `END_BUILD` → `RESOLVE_ROUND` → `CONTINUE` …），
「每回合一条」若逐字只在 `round-over` 那一次产出，那 `answer` / `placeTower` 的信息就全丢了，
而**正是 `answer` 那条最能说明「孩子选错了哪张卡」**。

⇒ **裁决（Dev 照办，不必重新决定）：`runEffects` 为**该回合的每一个 action**
产出一条 `TRACE`，由 `turn` 字段把它们归到同一回合号。**
⇒ console 上的逐条日志是「逐 action」的粒度；面板的「导出会话」才是「一整局」的粒度。
⚠️ **两条都要有守卫**（**G104**：同一回合内 `action` 逐字出现且条数 = 该回合 dispatch 次数）。

⚠️ **「数 dispatch 次数」的断言若走 Vue `watch` 必须 `flush: 'sync'`**（R-58）——
但本 story 的日志在 `applyAction` 里，**不走 watch**，天然同步 ⇒ 不适用 R-58。
**写清楚这一点**，否则下一个人会以为这里也该加 `flush`。

**AC-C4** ⚠️ **TRACE 只在 DEV 下打印**（裁决 2），且**不得**在渲染路径打日志（R-14）。
守卫 **G105**：`TRACE` 的那条 `console` 在 `import.meta.env.DEV` 分支内，
且全仓新增的 `console.*` **只允许**出现在 `app/effects-runner.ts` 与 `services/*`。
⚠️ 与 R-14 现有的「`src/core/**` 零 `console.`」守卫**并存，不重复** —— 那是两条不同的判据。

**AC-C5** ⚠️ **`Effect` 联合加成员 ⇒ 所有穷尽 `switch` 同步**（裁决 1）。
守卫 **G106**：`assertNeverEffect` 仍在 `default` 分支且在 `try` 之外
（那是 1.14 裁决 E4 的既有口径，一个字不许动）。

#### 🔥🔥 两条 0 红都是**等价变异**，不是缺守卫 —— 各自补了一条判据（R-51）

**M127（`initialState` 改成 `createInitialState()` 重算）首轮 0 红。**
根因：会话从**新开局**开始时，第一条 action 的 `prev` 与重算出来的开局
**逐字相等** ⇒ 那条路径上两种实现**输出完全一样**（G97 首版只从新开局起量）。
而 FR60 的真实场景是**断点续学**：`enterLevel()` 读档替换 `state.value` 且
**不 dispatch** ⇒ 会话还没开始录 ⇒ 第一条 action 的 `prev` 是**玩到一半的局面**。
⇒ 补的判据：造存档 → 换成新开局 → `enterLevel()` → 走一步 → 断言
`initialState.turn === 存档那份的回合` 且 `masteredEntryIds` 逐字相等。
（写这条时踩到 1.15 的写盘点表：存档是 `awaiting-build`，读档回来**没有正在问的题**，
所以第一条 action 用 `startRound()` 而不是答题。）

**M134（`Math.max(1, prev.hearts)` 改成 `prev.hearts`）首轮 0 红。**
根因：`prev` 是 `RESOLVE_ROUND` **之前**那份，而「心掉到 0」正是 resolve 那一刻发生的事
⇒ 真机上 `prev.hearts` **恒 ≥ 1** ⇒ 去掉夹取在所有**可达**输入上输出相同。
⇒ 这个夹取是**防御性**的（守「将来某条路径让 0 心继续往下走」），那种局面今天构造不出来
⇒ 补的判据直接**手造**那份 `reduced`（`hearts: 0` + `level-failed`）与 `prev`
（`hearts: 0` + `round-over`）喂给 `devAdjust`，断言夹到 1 且过 `assertInvariants`。
