## Story

As a 孩子,
I want 每一题都变成一个回合、答错的题会回来考我,
so that 没学会的词一定会被再教一次，直到我答对为止。

## Acceptance Criteria

> AC 编号为本 story 内部编号，与 epics.md 的 AC 列表一一对应处已注明。

### AC-1 Phase 是 State 的可辨识联合，含六种

`Phase` 用 `kind` 作判别式（**注意：Action 用 `type`，Phase 用 `kind`**，架构 `:842-849` 字面如此，
不是笔误）：

```ts
type Phase =
  | { kind: 'awaiting-answer'; question: Question }
  | { kind: 'awaiting-build';  unlocked: readonly string[]; sun: number }
  | { kind: 'resolving' }
  | { kind: 'round-over' }
  | { kind: 'level-complete' }
  | { kind: 'level-failed' }
```

- 回合内的两处无限等待（等选卡、等建造）**属于 State** —— 否则存档（决策 5）与合法性校验都无从谈起。
- `resolving` 是**真实的一帧状态**，不是瞬时值：`END_BUILD` 只切 phase 不结算，
  `RESOLVE_ROUND` 才执行攻击/推进/丢心。这样 UI 有战斗动画的落脚点，`runEffects` 也能拿到前后快照。
  六种 Phase 全部可被测试观测到，**不允许有死分支**。
- `unlocked` 与 `sun` 在 Phase 上重复出现，`State` 上也有一份 —— 见 §「自主设计清单」第 2 条的处置。

### AC-2 reducer 按阶段拒绝非法 action（FR54）

- `awaiting-answer` 阶段派发 `PLACE_TOWER` → `reduce` **抛错**。
- 其余非法组合同理（`awaiting-build` 派发 `ANSWER`、`resolving` 派发任何 action、`level-complete`
  派发任何 action …）。
- 边界断言放在 `core/` 内（廉价且天然覆盖所有调用路径），**不放组件层**（架构 `:572`）。
- 穷尽检查用 `assertNever`，新增阶段/动作时编译期报错。

### AC-3 答对结算（FR20、FR23）

- 阳光 `+= tier.sunPerCorrect`（单元 1 为 +50，经 `sunPerCorrectFor(unitNumber)` 读取，**不写字面量**）。
- 该题的 `entryId` 进入 `state.masteredEntryIds`；其塔卡进入 `state.unlocked`。
- **僵尸不被自动消灭** —— 塔是唯一能杀死它的东西。
- 该题此后**不再被 `nextQuestion()` 选中**（`deck` 数组本身一局内不变，见 AC-5）。

### AC-4 答错结算（FR21）

- 阳光**不变**（不扣不加）、`unlocked` 不增加。
- 该题**不进入** `masteredEntryIds` → 下一回合仍会被 `nextQuestion()` 选中。
- 该题对应的僵尸**照常留在场上**继续推进 —— 这是掉心的唯一来源。

### AC-5 题单一局内固定（FR22、FR24）

- `state.deck` 是本局题单的**固定全集**，一局内**数组本身永不变动**。
- 「已答对的题不再出现」由 `masteredEntryIds` 表达，`nextQuestion()` 跳过它们。
- `RESTART_LEVEL` 重打时：`deck` **原样复用**，`masteredEntryIds` 清空，
  `hearts` 重置为 `HEARTS`，`sun` 重置为 `initialSunFor(unitNumber)`，
  `towers` / `zombies` 清空（FR51 战场局末清空）。

### AC-6 僵尸入场时机（FR25）

- 该题对应的僵尸在**回合开始时**入场 —— 即 `createInitialState()` 与 `round-over --CONTINUE-->`
  这一次转换里完成，位置 `col = ZOMBIE_SPAWN_COL`。
- **答对与答错都会入场**，区别只在答对会给阳光和塔。

### AC-7 `resolving` 结算顺序固定（FR49）

顺序**不可交换**（`epics.md:838` 字面，Story 1.4 `combat.ts:4-17` 已锁定同一顺序）：

```
1. 攻击：每座塔各攻击射程内最靠近房子的僵尸一次（范围塔用 aoeTargets 溅射）
2. 推进：所有存活僵尸前进（减速生效时 1 格，否则 2 格）
3. 抵达：移动后 col <= HOUSE_COL 的僵尸消失，各丢 1 颗心
4. 判定：hearts <= 0 → level-failed
```

### AC-8 心与胜负（FR50）

- `hearts` 初始 `HEARTS`（=3），落在 `[0, 3]`。
- 耗尽 → `level-failed`。
- `deck` 全部 `mastered` → `level-complete`（在 `round-over --CONTINUE-->` 时判定）。

### AC-9 僵尸死亡无战利品（FR65）

塔打死僵尸**不产出任何阳光**。阳光只在答对时增长。

### AC-10 减速刷新而非叠加（FR35，AR27）

被同一座塔重复命中时**刷新** `slowTurnsLeft = SLOW_TURNS`，不累加。
（`applySlow()` 已实现，turn.ts 只需调用，不得自行加时长参数 —— `[CR]` D2 已删死参数。）

### AC-11 塔跨回合持久（FR82 / 断言 8）

`resolving` 跑完后已建塔**仍在场**，不被清空。只有一局结束（`level-complete` / `level-failed`
后的战场清空 / `RESTART_LEVEL`）才整体清空。

### AC-12 建造的 reducer 侧规则（FR27、FR30、FR33 的逻辑半边）

> UI 侧（两步放置、卡片高亮、射程预览）在 **Story 1.12**。本 story 只做 reducer 侧的合法性。

- `PLACE_TOWER` 扣除 `costOf(towerType, unitNumber)`；阳光不足 → 抛错。
- 目标格已占用 → 抛错（FR30）。
- **只能种已解锁的塔卡**，且塔的 `wordId` 来自该卡（FR23）。
- 同一张塔卡可反复建多株（FR33）—— `unlocked` 是数组不是集合，不因建造而移除。
- 建造阶段 `PLACE_TOWER` 成功后**仍是 `awaiting-build`**（自环），直到 `END_BUILD`。

### AC-13 不变量断言生效

`assertInvariants(state)` 在每个 action 之后执行（测试中每次 `reduce` 后调用，
或内置于 debug 断言路径），至少覆盖：

- `hearts ∈ [0, HEARTS]`
- `sun >= 0`
- 僵尸 `hp ∈ [0, ZOMBIE_HP]`（`createZombie` 已守）
- 场上僵尸仅存在于 `ZOMBIE_ROW` —— 由**类型**保证（`Zombie` 刻意没有 `row` 字段），无需运行时断言
- `grid` 与 `towers` 双向一致（每个 `Tower` 恰好占据 `cellKey(row, col)`，无孤立键）
- `unlocked ⊆ deck 的 entryId 集合`；`masteredEntryIds ⊆ deck 的 entryId 集合`
- 塔的 `towerType` 有效（`assertTowerType`）

### AC-14 tests/ 覆盖全部阶段转换与非法 action 拒绝

六种 Phase 全部被观测；每一条转换边至少一条测试；非法 action 每类至少一条 `toThrow` 测试。

- **模拟跑的是游戏真实实现，不是模型复刻** —— 不允许在脚本内重写一份回合逻辑。

### State 的最终设计（`types.ts` 内）

```ts
interface State {
  readonly unitNumber: number
  readonly phase: Phase
  readonly turn: number                                   // 当前回合号，1 起
  readonly hearts: number
  readonly sun: number                                    // 余额，唯一可写事实源
  readonly grid: Readonly<Record<string, string>>         // cellKey(row,col) -> tower id
  readonly towers: readonly Tower[]                       // 建造顺序，攻击顺序即此顺序
  readonly zombies: readonly Zombie[]
  readonly deck: readonly DeckEntry[]                     // 本局题单固定全集，一局内不变
  readonly masteredEntryIds: readonly string[]            // 本局已答对（与 Story 1.15 的 progress 分离）
  readonly unlocked: readonly string[]                    // 已解锁塔卡的 entryId 列表
}

interface DeckEntry {
  readonly entryId: string        // 带单元前缀，如 'u1-dog'（AR29；录音目录不分单元，不带前缀会撞名）
  readonly wordId: string         // 塔的显示名来源
  readonly towerType: TowerType   // 该词绑定哪种塔
  readonly card: Card
}

type OptionId = string
interface ImageOption { readonly id: OptionId; readonly imageSrc: string; readonly correct: boolean }
interface TextOption  { readonly id: OptionId; readonly text: string; readonly correct: boolean }
type Option = ImageOption | TextOption

interface Card {
  readonly kind: 'word' | 'keyword' | 'response'
  readonly promptText: string
  readonly options: readonly Option[]
}
type Question = DeckEntry     // Phase 携带的就是这道题的完整上下文
```

- **全部字段 `readonly`，全部 JSON 可序列化** —— 决策 5 要求序列化整个 state，
  不许有 `Map` / `Set` / `Date` / 类实例 / `undefined` 成员。`grid` 用字符串键即为此故。
- `card.kind` **不参与战斗**，仅用于渲染与卡型分布统计（FR14）。
- `isCorrect(card, chosenId)` 是唯一判定实现（架构 `:861-864`）；
  「唯一正确项」是 schema 级约束，运行时只**读** `option.correct` 不做数量校验（FR16）。

### Action 的最终设计（`actions.ts`）

```ts
type Action =
  | { readonly type: 'ANSWER';        readonly optionId: OptionId }
  | { readonly type: 'PLACE_TOWER';   readonly entryId: string; readonly cell: string }
  | { readonly type: 'END_BUILD' }
  | { readonly type: 'RESOLVE_ROUND' }
  | { readonly type: 'CONTINUE' }
  | { readonly type: 'RESTART_LEVEL' }

const answer        = (optionId: OptionId): Action => ({ type: 'ANSWER', optionId })
const placeTower    = (entryId: string, cell: string): Action => ({ type: 'PLACE_TOWER', entryId, cell })
const endBuild      = (): Action => ({ type: 'END_BUILD' })
const resolveRound  = (): Action => ({ type: 'RESOLVE_ROUND' })
const continueRound = (): Action => ({ type: 'CONTINUE' })
const restartLevel  = (): Action => ({ type: 'RESTART_LEVEL' })
```

⚠️ 只有 `PLACE_TOWER` 是架构给定的名字（`:578`、`:803`、`:853`），其余五个由本 story 拍板 ——
见 §自主设计清单。`'PLACE_TOWER'` **不得改名**。

`cell` 是 `cellKey(row, col)` 字符串（架构 `:579` 的示例即 `state.grid[action.cell]`）。

### turn.ts 编排契约（`[CR]` 移交项逐条接住）

1. **丢心判 `hasReachedHouse(col)`（`col <= HOUSE_COL`）**，不是 `hasPassedHouse`。
   两者差一回合；用错则僵尸站在房子上不掉心、关卡永不失败。
2. **行过滤在 turn.ts**：`state.towers.filter(t => t.row === ZOMBIE_ROW)` 才参与攻击。
   原语刻意不做（`[CR]` D4）。
3. **范围塔必须用 `aoeTargets()`** 逐只 `applyDamage`（`[CR]` D1）。
   若照 `selectTarget` 编排，范围塔静默退化成单体塔而**全部测试仍绿**。
4. **伤害/射程走 `damageFor(tower)` / `rangeFor(tower)`**，不得散取 `TOWER_STATS[...]`。
5. **攻击顺序 = `state.towers` 数组顺序**（即建造顺序），固定不变 —— `reduce` 无随机，
   同一串 Action 必须重放出完全相同的一局（决策 2 的红利）。
6. 移动用 `stepZombie()`，减速折算由它负责，turn.ts **不要**自己算格数。
7. 攻击阶段结束后立即剔除 `hp <= 0` 的僵尸，再进入推进阶段。

⚠️ **结算顺序的旧结论已被证伪**：旧注释里「先移动后攻击在减速塔上差一次命中」在本项目原语语义下
**不成立**（实跑 2 次 vs 3 次的说法已撤回）。若要验证顺序敏感性，
**必须用真实原语实跑，不得引用旧数字**。

⚠️ **`aoe.range = 2` 与实际 3 格条带覆盖无关** —— 伤害覆盖恒为同行 3 格，由 `aoeColumns()` 给出。
不要按 `rangeOf('aoe')` 算溅射范围。

### 断言的实测真值（`[CS]` 2026-10-13 实测，**禁止手算**）

建塔策略（钉死）：回合内阳光够就**在 `ZOMBIE_ROW` 的最低空列建塔**，可建列为
`[1..7]` —— 与 `balance-scan.py` 的 `range(1, cols-1)` **完全一致**，
排除 `HOUSE_COL`(0，房子格) 与 `ZOMBIE_SPAWN_COL`(8，僵尸入场格)。
⚠️ 策略改变会改变门槛数字，实测把可建列放宽到 `[0..8]` 门槛会从 4 变成 5 ——
因为 col 0 / col 1 两座塔会打在同一目标上，白白浪费前两次购买。

| 场景 | 掉心 | 结束回合 |
|---|---|---|
| 开局连错 1–2 题 | 0 | 跑满 10 |
| 开局连错 3 题 | 2（剩 1 心，未失败） | 跑满 10 |
| **开局连错 4 题** | **3 → `level-failed`** | **第 6 回合** |
| 开局连错 5 题以上 | 3 → 失败 | 第 6 回合（心已尽，回合数不再增长） |
| 后 7 题全错（4–10） | **0（全程 3 心）** | 跑满 10 |

断言 3 的逐回合轨迹（连错 4 题）：

```
回合 塔数 场上僵尸 掉心 剩余心
  1    0       1    0      3
  2    0       2    0      3
  3    0       3    0      3
  4    0       3    1      2      ← 第 1 只僵尸（第 1 回合入场）走满 4 回合抵达
  5    1       3    1      1      ← 第 2 只抵达；第 1 题答对 → 有钱建塔
  6    2       3    1      0      ← 第 3 只抵达 → hearts 0 → level-failed
```

> 僵尸于回合 r 入场 → 第 r+3 回合结算时抵达丢心（轨迹 8→6→4→2→0）。
> 这正是「连错 4 题」这个数字的来源。

**断言 4 的作用域必须写死为「前 10 回合内」。** 后半程答错的僵尸在第 10 回合时还没走完路程，
所以掉 0 心；**若把断言写成「直到本局自然结束都不掉心」，它是假的** —— 重考回合会把那些僵尸
推到房子。这是本 story 最容易被写成假绿的一处。
