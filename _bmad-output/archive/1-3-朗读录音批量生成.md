## §0 探测记录（`[CS]` 于 2026-10-13 实测，Dev 可直接采信，不必重跑）

用本机已配置的 CN region key（`/root/.mmx/config.json`，`region: cn`，`base_url: https://api.minimaxi.com`）实跑：

```
$ mmx speech synthesize --text "dog" --voice English_LovelyGirl --out /tmp/probe-lovelygirl.mp3
[Model: speech-2.8-hd]
{ "saved": "/tmp/probe-lovelygirl.mp3", "duration_ms": 864,
  "size_bytes": 15540, "sample_rate": 32000 }

$ mmx speech synthesize --text "I have a ball for my dog." \
    --voice English_LovelyGirl --speed 0.9 --out /tmp/probe-sentence.mp3
{ "duration_ms": 2340, "size_bytes": 39156, "sample_rate": 32000 }
```

**四条结论：**

1. ✅ **`English_LovelyGirl` 在 CN region 可用。** `mmx speech voices` 的枚举是残缺子集（英文只列了 6 个），**不是**可用性的判据。架构决策 7 的音色选择成立。
2. ✅ 单个单词 ≈ **15 KB**，教材长句 ≈ **39 KB**。推算：全年 200-400 词总入库体积约 **6-8 MB**，与 sprint-change-proposal 的风险 5.4 估算吻合。
3. ✅ `speed 0.9` 生效（长句比单词长得多，非截断）。
4. ✅ `--dry-run` 的请求体确认 `output_format: "hex"` —— **mmx CLI 内部即走 hex**，印证架构决策 7「不得用 url」不是空话。

**⚠️ 成本口径修正：** 官方按量计费 **speech-2.8-hd = 3.5 元/万字符**（国内站）。字符计费规则：汉字按 2 字符，英文/标点/空格按 1 字符。单元 1 实际估算 **≈ 450 字符 ≈ ¥0.16**，远低于 sprint-change-proposal:18 写的「≈¥5」（那是按更粗的粒度估的）。全量 200-400 词 ≈ ¥1.4。**AC-5 的费用预估按 3.5 元/万字符计算，不要沿用 ¥5。**

## Story

As a 开发者,
I want 一条可断点续传的批量脚本，把单元词条批量合成为统一音色的 mp3 并提交进仓库,
So that 孩子在任何设备上听到的发音都是**产品的确定常量**，而不是设备上恰好装了哪个语音引擎的偶然产物。

## Acceptance Criteria

### AC-1 脚本可执行

**Given** 一个干净的 clone
**When** 执行 `npm run generate:voice -- --dry`
**Then** 脚本存在且退出码为 0，输出词条数、总字符数与费用预估
**And** 该命令**不发起任何网络请求**
**And** 文件为 `scripts/generate-voice.ts`，经 `tsx` 执行（与 `validate-content` / `balance-sim` 同一模式）

> 📎 `[CS]` 补充：`package.json` 当前**没有**这个 script，本 story 需新增。

### AC-2 词表来源与 id 格式

**Given** `src/content/` 当前为空（Story 1.6 未开工）
**When** 脚本读取词表
**Then** 读一份**本 story 新建**的词表文件（建议 `scripts/data/voice-entries.json`），**不得** import `src/content/` —— 那会撞 TS6307（见 §3.2）
**And** 词表每条含 `{ id, text }`，`text` = **卡面题面原文**
**And** 每个 `id` 必须匹配 `/^[a-z0-9]+(?:-[a-z0-9]+)*$/`（与 `pronunciation.ts:158` 的 `ENTRY_ID_PATTERN` **逐字一致**）
**And** 每个 `id` **带单元前缀**（`u1-dog`）—— 不带前缀则不同单元同名词撞名，**撞名后果是某个词发错音，对学习类产品是静默的严重错误**（`game-architecture.md:375`）

> 📎 **移交 Story 1.6：** 1.6 录入 `src/content/units/unit-01.json` 后，词表须同步为正式内容并重跑一次。**断点续传使第二次只补新增词条**（AC-6）。
>
> 📎 **移交 Story 1.7 / 1.8：** 本 story 只管录音，**不管词图**。词图由 1.7 / 1.8 生产在 `public/assets/words/unit-01/<id>.svg`，与录音**共用同一个 id**。

### AC-3 音色探测门（不可协商）

**Given** `English_LovelyGirl` 音色
**When** 脚本首次实跑（`--dry` 之外）
**Then** **第一个词条即试跑**，失败则**立即报错退出**（退出码非 0），打印 API 返回的 `base_resp.status_code` 与 `status_msg`
**And** **不得静默换一个可用音色继续跑** —— 音色一致性是本 story 的全部价值所在
**And** 音色 / 模型 / 语速三者写成文件顶部的 `UPPER_SNAKE_CASE` 常量（`game-architecture.md:636` 已指定本文件的参数归属）：

```ts
const VOICE_MODEL  = 'speech-2.8-hd'
const VOICE_ID     = 'English_LovelyGirl'   // 英式女童声
const VOICE_SPEED  = 0.9
const VOICE_FORMAT = 'mp3'
```

> ⚠️ **改这三行 = 全量重生成 200-400 个词。** 注释里写明这句话。
> 📎 参考：§0 已实测该音色可用，此门是防**未来**模型下架 / 静默换权重（架构决策 7 已记录 `speech-01-*` 从模型列表消失的先例）。

### AC-4 必须 hex，禁止 url

**Given** 合成请求体
**Then** `output_format` **必须**是 `"hex"`，**不得**是 `"url"`
**And** 响应里的 `data.audio` 是十六进制字符串，写盘前须解码为二进制再 `writeFileSync`
**And** 代码注释写明理由：**`url` 返回的链接 24 小时过期，分批生成会在几天后静默拿到损坏文件**（架构决策 7 硬约束 2）

### AC-5 `--dry` 预估模式

**Given** `--dry` 参数
**When** 执行
**Then** 逐条打印「id → 字符数 → 该条费用」，并给总计
**And** 按 **3.5 元/万字符** 计费（见 §0 成本修正）
**And** **一个网络请求都不发**

### AC-6 断点续传

**Given** 脚本被中断（网络失败 / Ctrl-C）
**When** 重新运行
**Then** **已存在的 mp3 文件被跳过**，不重复生成、不重复计费
**And** 日志逐条打印 `[voice] skip <id>（已存在）`

> ⚠️ **这是音色一致性的保障，不是性能优化**（epics.md:710 原文）。跨批次生成的文件必须听上去是同一个人念的。
> **验收方式**：先跑全量 → 删掉其中 3 个 → 重跑 → 确认那 3 个被重新生成、其余 skip。

### AC-7 重试上限与失败清单

**Given** 某个词条重试多次仍失败
**When** 达到重试上限（建议 3 次，指数退避）
**Then** 打印失败的**词条 id 与错误码**（取自响应的 `base_resp.status_code`）
**And** 脚本结束时的**退出码非 0**
**And** **已成功的文件全部保留** —— 断点续传语义，下一次只补失败的

### AC-8 API key 的处理

**Given** `MINIMAX_API_KEY` 环境变量
**When** 脚本启动
**Then** **只读**，**不写入任何文件、不打印到日志、不出现在错误信息里**
**And** key 缺失时**明确报错退出（退出码非 0）**，**不静默跳过**
**And** 尝试读取仓库根的 `.env`（`.env` 已在 `.gitignore:27-32`，安全）；`.env.example` 里只写 `MINIMAX_API_KEY=` 空占位，**不得**含真实 key

### AC-9 产物落位与运行时契约对齐

**Given** 生成的 mp3
**Then** 落在 **`public/assets/audio/voice/<词条id>.mp3`**
**And** **不按单元分层**（`audio/voice/` 是平铺的 —— 目录结构里 `audio/{music,sfx,voice}/` 没有单元子层，`game-architecture.md:754-758`）
**And** 该 URL 与 `pronunciation.ts:214` 的 `new Audio(\`${RECORDING_BASE_PATH}${entryId}.mp3\`)` **逐字对齐**
**And** 脚本**不**把音频写进 `src/` 或 bundle（架构决策 3：图片与音频都不进 JS bundle）
**And** `.gitignore` **不**忽略 `*.mp3` —— **生成的 mp3 全部提交进 git**（架构决策 7 硬约束 1）

### AC-10 人工试听验收（人耳，非代码可代做）

## Dev Notes

### 1. 本 story 在架构里的位置

`game-architecture.md:379-430` 决策 7「朗读通路：预生成录音为主，设备 TTS 为辅」是本 story 的全部依据。主通路 `public/assets/audio/voice/<词条id>.mp3`，辅通路 `speechSynthesis` 链降级，降级必须收敛在 `playPronunciation(text, entryId?)` 这一个接口上（1.2 已交付，**本 story 一行都不用改它**）。

**为什么录音优先于设备 TTS**（架构 `:391` 自述的反证，Dev 应理解而非只背）：旧项目在同一台华为平板上大概率走了 fallback（`gdd.md:519`）；EMUI + Chrome 上 `speechSynthesis` 可能报 0 voices（1.2 §13）；**Android WebView 完全不支持原生 TTS**（chromium issue 710238）。设备装了什么引擎就用什么音色 —— 发音因此**不可复现**，这与架构自述的原则（epics Story 3.4「音色选择以教材录音为准绳，而非以设备上有什么为准」）直接冲突。

### 3. 四个最容易踩的坑

#### 3.1 断点续传会把半截文件当成功（AC-6 的隐藏地雷）

跳过判据是 `existsSync`。若上一次运行在 `writeFileSync` 写到一半时被杀（Ctrl-C、断电、磁盘满），磁盘上会留下一个**截断的 mp3**，而它**看起来是存在的** —— 下次跑会被 skip，永久留下一个播不出声的录音。

而且这类失败**完全静默**：运行时 `new Audio()` 收到 `error` 事件，`playRecording` 老老实实降级到设备 TTS，孩子听到的只是「音色不对」，没有任何报错指向这个文件。

**解法：** 先写 `<id>.mp3.tmp`，`writeFileSync` 完成后 `renameSync` 到正式名（同一目录内 rename 是原子的）。跳过判定只认正式名。

#### 3.2 脚本不要 import `src/`（TS6307）

`tsconfig.node.json` 的 `include` 只有 `["vite.config.ts", "vitest.config.ts"]`，**不含 `scripts/**`** —— 这是 Story 1.1 的有意决定（1.1 §14 第 5 条：「如果加了，Story 1.4 让 `balance-sim.ts` import `src/core/` 的 reducer 时会命中 **TS6307**」）。

**推论：`scripts/generate-voice.ts` 不受 `vue-tsc -b` 覆盖，类型错误不会被 `npm run build` 拦住。**

⚠️ 因此：**绝对不要**让脚本 `import { ENTRY_ID_PATTERN } from '../src/services/pronunciation'` 之类的共享 —— 那会撞 TS6307。**做法是把正则复制一份在本文件里，并加一条测试断言两边一致**（AC-12 第一条）。这是一处**有意的、有测试兜底的重复**，不是疏忽。

> 📎 若将来要真正共享，只能给 `tsconfig.node.json` 补 `"references": [{ "path": "./tsconfig.core.json" }]` —— 那是 **Story 1.4** 的活，1.1 已明说「这个坑留给 Story 1.4 踩，不要现在提前加」。

#### 3.3 变异验证是本项目的铁律

1.2 的 Change Log 记录了一条教训：**「反向验证没做就采信『这条断言有洞』，代价是往套件里塞一条永远不会失败的断言。」** 当轮撤回了一条 patch，就是因为变异验证证明它抓不到任何旧断言抓不到的东西。

**因此：AC-12 的每一条守卫用例，写完后必须做一次变异验证** —— 把被守卫的代码改坏，确认用例**变红**，再复原。尤其是 AC-12 第一条（id 正则）：把词表里某个 id 改成 `U1_Dog`，测试必须当场变红。

### 4. 词表的 id 前缀：为什么不能省

`game-architecture.md:375` 原文：

> id 带单元前缀（`u1-dog`、`u2-apple`）—— 录音目录 `audio/voice/` **不按单元分层**，id 不带前缀则不同单元的同名词会撞名，而**撞名后果是某个词发错音（对学习类产品是静默的严重错误）**。
