**范围分类：** **Moderate** —— 需回填 4 个产物 + 新增 1 个 story，架构核心决策需修订

## 1. 问题陈述

### 变更内容

用 MiniMax `speech-2.8-hd` 在**开发期批量预生成**全部单词、关键词、回应的朗读音频
（`speech-2.8-hd` + 音色 `English_LovelyGirl`，英式女童声），随产品离线分发。

一次性生成成本 ≈ **¥5**（400 词含句子），语音 API 无运行时调用。

### 为什么这构成一次纠偏

原架构把**设备 TTS 定为主通路、预置录音定为降级**。本次变更把两者对调，理由是：

本作的核心是英文单词的认读质量，而设备 TTS 是跨设备表现最不可控的一环 ——
发音取决于设备装了哪些语音引擎。**架构文档自己已记录反证：**

- 旧项目在华为设备上大概率走了 fallback（「能发声 ≠ 音色与教材一致」，`gdd.md:519`）
- Story 1.2 §13 记录 EMUI + Chrome 上 `speechSynthesis` 可能报 0 voices
- Story 1.2 §13 记录 Android WebView **完全不支持**原生 TTS（chromium issue 710238）

一个取决于设备偶然状态的核心学习入口，与架构自述的原则矛盾：

> 音色选择以**教材录音**为准绳，而非以设备上有什么为准。（`epics.md` Story 3.4）

预生成录音把发音变成**产品的确定常量**，而非设备的偶然产物。

### 附带解决

原 GDD 的降级方案排序建立在「设备 TTS 基本可用」的假设上。本次变更同时解决：

- 长句发音清晰度的验收问题（不再依赖设备 TTS 的表现）
- 音色与教材不一致的问题（音色在生成时即固定）

## 4. 详细变更提案

### 4.1 `game-architecture.md` — 决策 7（核心）

**OLD**（`game-architecture.md:379-401`）：

```markdown
### 7. TTS 音色与降级

**音色优先级（沿用 legacy 链）：**
Google UK English → Google US English → Microsoft Hazel/Susan
→ Samantha / Karen → 任意 en-US → 任意 en

英式优先（上海版教材录音多为英式），但**架构上不得假设首选音色存在**。

**朗读参数（做成可配置常量，Epic 1 现场调）：**
| 单词 | rate 0.85 / pitch 1.05 | 沿用 legacy |
| 长句 | rate 0.9（起点） | legacy |

**降级通路：**
- 启动时探测 `window.speechSynthesis` 可用性与可用音色数
- **不可用时自动降级为预置录音**
- 降级须在架构层有固定位置（统一的 `playPronunciation(text)` 接口）

**硬约束：TTS 播放失败绝不阻断回合流转。**
```

**NEW**：

```markdown
### 7. 朗读通路：预生成录音为主，设备 TTS 为辅

**主通路：预生成录音** —— `public/assets/audio/voice/<词条id>.mp3`

| 项 | 值 |
|---|---|
| 生成方式 | 开发期批量调用 MiniMax TTS API |
| 模型 | `speech-2.8-hd` |
| 音色 | `English_LovelyGirl`（英式女童声） |
| 覆盖范围 | **全部单词 + 关键词 + 回应**（全量预生成，非仅长句） |
| 成本 | 一次性 ≈ ¥5 |

**为什么录音优先于设备 TTS：** 本作核心是英文单词的认读质量，而设备 TTS 是
跨设备表现最不可控的一环 —— 架构已记录 EMUI 可能 0 voices、Android WebView
完全不支持原生 TTS。设备装了什么引擎就用什么音色，发音因此不可复现。
预生成录音把发音变成产品的确定常量。

**辅通路：设备 `speechSynthesis`**

仅在录音文件缺失 / 加载失败时兜底。音色沿用 legacy 链降级：

```
Google UK English → Google US English → Microsoft Hazel/Susan
→ Samantha / Karen → 任意 en-US → 任意 en
```

**硬约束不变：朗读失败绝不阻断回合流转。**
降级通路固定在 `playPronunciation(text)` 统一接口，不是临时 if。

**⚠️ 两条不可协商的生成约束：**

1. **一次性全量生成，mp3 提交进 git，永不重新生成。**
   TTS API 无 `seed` / `temperature` 参数，不保证跨批次音色一致；且已观察到
   `speech-01-*` 在 API 枚举中仍被接受、却已从模型列表消失 —— 模型下架或静默
   换权重会让分批生成的文件前后不一致。
2. **生成必须用 `output_format: "hex"`，不得用 `"url"`。**
   `"url"` 返回的链接 **24 小时过期**，分批生成会在几天后静默拿到损坏文件。
```

**Rationale：** 主备反转。设备 TTS 降级为兜底，其代码不删除 —— `playPronunciation()`
统一接口与启动时探测逻辑全部保留，仅主备顺序对调。

### 4.2 `game-architecture.md` — 目录结构与 id 命名

**OLD**（`game-architecture.md:724-727, 774`）：

```
public/assets/
  ├── words/unit-01/<词条id>.svg
  ├── towers/<塔型id>.svg
  └── zombies/<僵尸id>.svg

| 词条 id / 素材文件名 | kebab-case，**文件名 = id** | `dog.svg` |
```

**NEW**：

```
public/assets/
  ├── words/unit-01/<词条id>.svg
  ├── audio/voice/<词条id>.mp3      ← 新增：朗读录音，不按单元分层
  ├── towers/<塔型id>.svg
  └── zombies/<僵尸id>.svg
```

**词条 id 格式：带单元前缀的 kebab-case。** 例：`u1-dog`（单元 1）、
`u2-apple`（单元 2）。对应素材文件名为 `u1-dog.svg` / `u1-dog.mp3`。

**Rationale：** 「文件名 = 词条 id」规则同样适用于音频 —— 词图与录音靠同一 id 关联。
id 必须带单元前缀，因为录音目录**不按单元分层**，若 id 仅为 `dog`，不同单元的
`dog` 会撞名。撞名后果是某个词发错音 —— 对学习类产品是静默的严重错误，
而 200-400 词靠人工保证全局不重名迟早会破。

> ⚠️ **连带影响：** 架构文档与 epics 中所有 `dog.svg` 形式的示例需改为 `u1-dog.svg`。
> 当前无已生成资产（词图一张都未画），故仅为示例文字调整。

## 5. 风险登记

### 5.1 🚩 AIGC 标识合规（**不进 GDD，按用户决定**）

《人工智能生成合成内容标识办法》（2025-09-01 生效）第 4 条要求音频在起始、末尾或
中间添加语音/节奏提示标识；提供下载导出时**文件本身必须含标识**。

本项目分发 200-400 个 mp3 给终端用户，**是否落入适用范围需咨询律师** ——
这不是本提案能给出的结论。

低成本缓解手段（若判定需要）：生成时在每个词前加极短引导音，或随包附
`ai-disclosure.mp3`。

> 经与提出人确认，本项**不写入 GDD**，仅在本提案登记。

### 5.2 音色一致性

API 无 `seed` / `temperature`，跨批次生成不保证一致。
**缓解：** 一次性全量生成 + 提交 git + 永不重新生成（已写入 4.1 的硬约束）。

### 5.3 模型下架

`speech-01-*` 已从模型列表消失但仍在 API 枚举中被接受。若 `speech-2.8-hd`
将来同样下架或静默换权重，400 个文件会与新生成的不一致。
**缓解：** 同 5.2 —— 不重新生成。模型变更需要显式的迁移决策。

### 5.4 bundle 体积

+约 8MB（400 词 × ~20KB）。
**缓解：** 决策 6「按单元预取」+ Service Worker 按单元缓存，已在架构内。

### 5.5 外部服务依赖

录音生产依赖 MiniMax API 可用且 token 有效。
**缓解：** 一次性生成后产物入 git，此后不再依赖外部服务。
