## 拆解原则

**垂直切片优先。** 首个 Epic 用一个完整单元端到端跑通全部系统，先验证孩子愿不愿意玩，再投入内容量生产。

依据：旧版本（tag `legacy-v5.x-final`）走功能广度优先的路线，历经 5 个大版本仍只积累了 9 张词图，且因学习内容缺失被家长否决。内容量生产是本项目最大的产能风险，必须在投入前先验证。

---

## Epic 1 —— 垂直切片：单元 1 端到端

**目标**

一个完整教材单元从进入关卡到通关的完整链路全部打通，孩子能独立完成并愿意反复玩。

**TTS 已在旧项目验证可用。** 旧实现（`legacy-v5.x-final:src/systems/SpeechService.ts`）用的就是同一套 Web Speech API，且已确认能在该华为设备上发声。**Epic 1 不需要重新验证「能否发声」，只需确认发音效果。**

**可交付物**

孩子打开游戏 → 进入单元 1 → 完成全部题目 → 通关 → 看到进度推进。

**范围内**

| 模块 | 内容 |
|---|---|
| **发音确认** | 试听教材长句（`I have a ball for my dog.`）的发音清晰度与英/美音色。旧项目只念过 7 个植物名，长句与音色从未验证 |
| TTS | 朗读题目，卡面可点击重听。沿用旧项目 `preheat()` 的音频解锁做法 |
| 卡型 | 单词卡、关键词卡、回应卡（单元 1 须**至少各含一道**，以验证完整链路） |
| 答题判定 | 选对 / 选错，立即反馈 |
| 塔解锁 | 答对解锁对应词塔卡，仅可种该词对应的塔 |
| 放置 | 两步操作：点卡片 → 点格子；5×9 网格；不铲除不拖拽 |
| 塔 | 三种战斗类型（直射/减速/范围），首版数值见 GDD |
| 僵尸 | 通用敌人，一次一个；100 血，每回合 2 格，只有塔能杀死；开局连错 7 题即失败 |
| 经济 | 阳光：单元 1-4 初始 **0**、答对 +50、答错不变；建造时扣除造价（50/50/75）。答对一次 = 恰好一株塔 |
| 胜负 | 3 心；僵尸走到房子掉心；三心耗尽失败并重打本局 |
| 音效 | 答对/答错/建塔/僵尸死亡/掉心/通关/失败 |
| BGM | 战斗循环单曲 |
| 题单规则 | 答错的词留在题单内循环，直到答对；重打时题单不变 |
| 进度持久化 | 单元内答题进度，断点续学 |
| 进度可见 | 「第 1 单元 · 21/60」 |
| 内容 | 单元 1 全部词汇（约 15-30 词）与句子 |
| 美术 | 2-3 株植物（扁平矢量）+ 单元 1 词图（约 15-30 张） |

**范围外**

- 单元 2 及以后
- 塔的升级、技能、铲除、拖拽
- 难度阶梯的跨关分布（Epic 3）
- 数值精细调优（Epic 4 —— Epic 1 先用 GDD 中的首版数值跑通）

**依赖**

无。Epic 1 是根。

**完成的判据**

1. 孩子能独立完成单元 1（不需要家长协助操作）
3. 孩子**愿意反复玩**单元 1 —— 这是「逐步补」策略成立的前提，也是本 Epic 的真正验证目标
4. 单元 1 的题目、词图、塔绑定内容全部录入完毕
5. **失败确实可能发生** —— 开局连续答错 **7 题**时本局应当失败（3 心耗尽）。该门槛由 `balance-sim.py` 实测得出，非估算。若实现跑出的门槛与此显著不符，说明战斗数值有偏差，须重跑模拟校准

## Epic 2 —— 内容流水线与单元扩展

**目标**

从「手工做一个单元」扩展到「按流水线批量生产全书单元」。

**可交付物**

上海版一年级全年两册（约 16-20 单元）全部可玩，孩子能从单元 1 连续打到最后一关。

**范围内**

| 模块 | 内容 |
|---|---|
| 内容数据格式 | 单元 → 词汇/句子 → 卡型 → 题目 → 词图 → 塔型绑定 |
| 内容流水线 | 教材内容录入流程，词图按单元增量补充 |
| 单元切换 | 完成一个单元自动进入下一单元 |
| 总进度 | 跨单元的全局进度显示 |
| 内容 | 全年两册全部单元 |

**范围外**

- 新玩法、新卡型、新塔型
- 难度阶梯的分布策略（Epic 3）

**依赖**

Epic 1

**完成的判据**

孩子能从头打到尾，全书覆盖无缺单元。

## Epic 3 —— 难度阶梯落地

**目标**

把支柱 3（逐层上移）落到具体的内容编排上——早期单元以单词卡为主，逐步引入关键词卡与回应卡。

**可交付物**

单元 1-3 以单词卡为主，单元 4 起逐步混入关键词卡与回应卡，全程难度平滑上升。

**范围内**

| 模块 | 内容 |
|---|---|
| 卡型分布规则 | 按单元序号分配卡型，构成难度曲线 |
| 难度过渡 | 从单词卡到句子层的引入点与节奏 |
| 回应卡引入 | 问句与短语的回应选项编排 |

**范围外**

- 战斗层难度变化（僵尸变强、路径变复杂）—— GDD 已决定战斗层全程一致，不做

**依赖**

Epic 2

**完成的判据**

孩子在前 3 关不因句式过早而受挫，在后半程能完成句意理解与应答。

---

## Epic 4 —— 打磨

**目标**

基于实际试玩数据调优，不做玩法扩张。

**可交付物**

数值调优后的版本，UI 细节修正，音频（若纳入范围）。

**范围内**

| 模块 | 内容 |
|---|---|
| 数值调优 | 塔伤害/射程/费用、僵尸血量/速度、阳光速率——依实际试玩数据调整，每次改动后重跑 `balance-scan.py` |
| 音频打磨 | 音效品质、BGM 选曲（链路已在 Epic 1 跑通） |
| 节奏调优 | 每题周期长度、每局题数 |
| 移动端布局 | 平板竖屏布局校验；语音浮层不遮挡战场 |
| UI 细节 | 反馈动效、高亮、状态提示 |

**范围外**

- 新玩法、新卡型
- 公开分发所需的适配

**依赖**

Epic 2

**完成的判据**

孩子在连续试玩中不再出现挫败点或卡关。

## 关键风险

| 风险 | 影响 Epic | 应对 |
|---|---|---|
| **词图产能** —— 全年 200-400 词需 200-400 张插画 | Epic 2 | 已采用「逐步补」：每个单元做完再做下一个单元的图。若产能持续不足，需重新评估内容范围或引入复用/程序化方案 |
| **教材长句发音效果未验证** | Epic 1 | TTS 能否发声已由旧项目确认，风险大幅降低。但旧项目只念过 7 个单词，长句韵律与英/美音色未测。**Epic 1 首次试玩即确认**；不可接受则改预置录音 |
| **孩子试玩意愿未知** | Epic 1 | Epic 1 的核心验证目标。若孩子不愿玩，需回退重新审视设计，而非继续投入 Epic 2 |
| **阳光递增不改变难度** | Epic 2-4 | 已实测确认：塔为持久资产，递增阳光不改变失败门槛。难度递增须由卡型与词汇承载（Epic 3），不可依赖阳光 |
