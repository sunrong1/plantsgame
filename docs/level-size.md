# 局规模 census —— 每个教材单元切成几局、每局几题

> 🔥 **本文件回答一个问题**：教材 24 个单元按「一局 = 10 题」切下去，
> **哪些单元的局会短到不成局**。
>
> ⚠️ **换源之后这个问题才第一次成立**（Story 2.10 换源批次，2026-10-27）。
> 换源前单元 1 有 37 条词条 ⇒ 每局都是满 10 题 ⇒ 「一局 = 10 题」与
> 「1 关 = 1 教材 Unit」不冲突。换成教材的真实规模之后，**24 个单元里
> 13 个的末局不足 5 题、10 个单元整本只有一局** ⇒ 冲突成立。

---

## 1. 口径

### 1.1 一个单元的词条总数 N

```
N = 该单元的单词卡数 + 该单元的去重句卡数
```

- **单词卡数** = 教材 `Look and learn` 词表里的**词数**（多词词条整体算 1 个：
  `ice cream` 是 1 个词条，不是 2 个）。
- **去重句卡数** = 教材 `Say and act` 里的**句子**条数，
  **同一句只算一次**（教材的转写里同一句话会在多个演练段落里重复出现），
  **场景 / 类别标签不算**（`Greetings 问候`、`On Sunday afternoon 星期天的下午`
  这类没有终止标点的条目不做卡）。

⇒ **N 就是内容层会为这一单元交付的卡数** —— 已交付的两个单元可以验：
单元 1 = 2 词 + 4 句 = **6** 条（`unit-01.json` 逐条对得上），
单元 2 = 4 词 + 7 句 = **11** 条（`unit-02.json` 逐条对得上）。

⚠️ **句子卡在内容层分成 `keyword` 与 `response` 两种卡型**（见
[卡型分布规则](./card-distribution.md)），但**总数不变** ⇒ N 与卡型无关。

### 1.2 局序列

局序列 = 把 N 按 `QUESTIONS_PER_LEVEL`（= **10**，`src/core/deck-slice.ts` 的唯一定义处）
切成若干局：**末局不足 10 题就是不足**（单元 2 的末局是 **1 题**，这不是 bug）。

⚠️ **`QUESTIONS_PER_LEVEL` 保持 10**（2026-10-27 用户裁决：保持 10，但重算平衡阈值）——
本文件**记录**这个口径造成的后果，**不**改它。

### 1.3 这份 census 的事实源

- **教材语料** = `docs/textbook-oxford-shanghai/01a-units.md` 与 `01b-units.md`；
  解析器 = `tests/helpers/textbook-corpus.ts`（**全仓唯一**的教材解析器）。
- **切片规则** = `src/core/deck-slice.ts` 的 `QUESTIONS_PER_LEVEL`。
- ⇒ 本文件里的每一个数都能**从代码复算**（§5），并且**有守卫盯着**
  （`tests/content/level-size-doc.test.ts` 的 **G341**）。

| 汇总 | 单元数 | 单元 |
|---|---|---|
| 末局不足 5 题 | **13** | 2、3、4、10、11、12、13、15、16、20、22、23、24 |
| 整本只有一局、且这一局只有 4–5 题 | **9** | 4、5、10、11、12、13、20、22、23 |
| 单局不超过 5 题（含单元 24 的 3 题） | **10** | 4、5、10、11、12、13、20、22、23、24 |

⇒ 最短的一局是 **1 题**（单元 2 的末局），最长的一局是 **10 题**
（9 个单元的首局：2、3、6、7、15、16、17、18、21）。

⚠️📎 **2026-10-27（Story 2.10 `[CR]`）的更正**：本文件首次落笔时，
Story 文档里记的是「**14**/24 单元末局 < 5 题、**6** 个单元总共只有 4–5 题」。
按**修好之后的**教材解析器（剥演练序号、丢弃被页面截断的残条）实算，
正确值是 **13** 与 **9**（另有单元 24 单局 3 题）⇒ 旧的两个数**作废**。

## 4. 失败门槛按真实局规模重算

「一局 = 10 题」是**题单编排**的口径，失败门槛是**战斗数值**的结果
（见 [R-22](./rules/range-and-balance.md)）—— 局规模一变，门槛**要重测**。
`npm run balance-sim -- <单元号>` 现在**另出一张**「按真实局规模的失败门槛」表
（Story 2.10 `[CR]` 补丁 15），它用 `src/core/deck-slice.ts` 的 `sliceDeckForLevel`
切**真实内容**（不是合成题单）。

2026-10-27 实测（单元 1 与单元 2 是当前仅有的两个已录内容的单元）：

| 真实局 | 题数 | 失败门槛 | 与 10 题合成局相比 |
|---|---|---|---|
| 单元 1 · 局 1 | 6 | **连错 3 通关 / 连错 4 失败** | **相同**（门槛没动） |
| 单元 2 · 局 1 | 10 | **连错 3 通关 / 连错 4 失败** | 相同（就是满 10 题） |
| 单元 2 · 局 2 | 1 | **连错 5 题仍通关**（表里没再往上测） | **更宽**（不是更窄） |

⚠️ **机制**（为什么短局的门槛更宽）：一局在**全部题目答对**时就结束 ⇒
局越短，结束得越早 ⇒ 僵尸压过来的回合越少 ⇒ 掉的心越少。
单元 2 的末局只有 1 题 ⇒ 连错 4 题之后第 5 回合答对，这一局**当场结束**，
僵尸只吃到了 2 颗心 ⇒ 仍通关。

⚠️ **对评审时那条判断的更正**（R-21）：评审时写的是
「『连错 3 通关 / 连错 4 失败』是按 10 题一局标定的，**对 4–6 题的局不成立**」。
实测**只对 1 题的局成立** —— 6 题的局（单元 1）门槛**与 10 题的局完全相同**。
⇒ 「6 题的局门槛会变」这个前提**未经实测**就写进了故事文档，已按 R-21 更正。

## 5. 复算方法

```bash
# 在仓库根目录执行。需要仓库自带的 tsx（已在 devDependencies）。
npx tsx -e "
import { loadTextbookBooks, normalizeEnglish, textbookUnitOf } from './tests/helpers/textbook-corpus.ts'
import { QUESTIONS_PER_LEVEL } from './src/core/deck-slice.ts'
const books = loadTextbookBooks()
for (let n = 1; n <= 24; n += 1) {
  const { unit } = textbookUnitOf(n, books)
  const sentences = new Set(unit.sentences.map(normalizeEnglish))
  const N = unit.vocabulary.length + sentences.size
  const levels: number[] = []
  let left = N
  while (left > 0) { const c = Math.min(QUESTIONS_PER_LEVEL, left); levels.push(c); left -= c }
  console.log(n, unit.vocabulary.length, sentences.size, N, levels.join(' + '))
}
"
```

⚠️ **这条命令 import 了 `tests/` 下的解析器** ——
`scripts/balance-sim.ts` **不得**这样做（它的纪律是「不 import `src/` 以外的东西」，
见该文件抬头）⇒ **census 只能由内容 / 守卫侧算**；
脚本侧能拿到的只有**已录内容**的真实局（当前：单元 1、2）。

守卫：**G341**（`tests/content/level-size-doc.test.ts`）逐格核对本文件 §2 的表
与 §3 的三个汇总数字 ⇒ 教材改了、切片口径改了，本文件会红。
