# 数值与平衡

> **本文件的每一条都涉及产品决策。** 改它们之前必须问人 —— 测试跑绿不等于可以改，
> 数值断言恰恰会因为你改了而红。

### R-20 数值平衡参数禁止擅自改

**规则** 以下属产品决策，改动前必须问人：

- 心数上限
- 阳光递增公式
- 僵尸血量 / 速度
- 关卡阈值

**依据** 这些数字是 GDD 与 AR23/AR24 的产品承诺，不是实现细节。「测试绿了所以可以调」是误读 —— 断言红正是它在告诉你这是设计决定。

**守卫** `tests/core/balance.test.ts`（「僵尸满血 100、每回合 2 格」、「减速 50% 持续 3 回合」、「三塔型属性与 GDD 塔型表逐字一致」、「初始阳光与答对增量与 FR63 第 1 档一致」）、`tests/core/assertions.test.ts`（AR23/AR24）、`tests/core/reducer.test.ts`（「初始心数 / 阳光 / 回合号 / 战场」）、`tests/core/combat.test.ts`（「全部 9 列的命中次数逐列锁死」）

**首现** Story 1-4

### R-21 实测值优先于文档值

**规则** 当文档里的数值结论被实测推翻时：**断言按实测写**，并**在同一 story 内同步更正源文档**（GDD / decision-log / `epics.md`）。

**依据** 本项目的历史反复证明文档里的手算不可信 —— decision-log 记录了「阳光孤儿机制」「模拟器两个 bug」「射程窗口按双向算」「减速塔 6×25」四次手算错误。把已知错值原样抄进新 story 等于把它**再固化一次**，并让后续 3 个 story 继续引用它当论据。

**How** 既不要二选一地把错值搬进新文件，也不要跳过流程去跑 `[CC]`（会把一个顺手能修的数字问题升级成一次独立往返）。正确处置是：断言按实测写 + 把「更正源文档」列为该 story 的强制交付物 + 在 Dev Notes 附逐回合轨迹作证据。

**守卫** ⚠️ **无守卫**（这是流程纪律，不是可自动化的不变量）

**首现** Story 1.4

### R-22 平衡模拟是 TypeScript，不得另起一份数值

**规则** `npm run balance-sim` 跑 `scripts/balance-sim.ts`，它 import 真实的 `core/` reducer。**不得**用 Python 或任何复制数值的独立实现。

**依据** 两份数值必然漂移。旧的 `balance-scan.py` 已被删除，原因见 R-23。

**守卫** ⚠️ **无守卫** —— 没有测试扫描 `scripts/balance-sim.ts` 的 import。`core-boundary.test.ts` 只断言 npm script 存在，`reducer.test.ts` 里是注释级断言。**这条规则目前纯靠约定。**

**首现** Story 1.1（CLAUDE.md 硬约束 10）

### R-23 模拟器不得静默丢实体

**规则** 任何按位置 / 时间步索引的容器在模拟多实体时，必须先确认同一容器不冲突（入场点 vs 步长 vs 存量），或改用 list + 稳定 id。**升级验证：再验一遍「实体数量守恒」** —— 把模拟器跑出的场面实体数与按规则手推的数对上。

**依据** `balance-scan.py` 用 `dict[col, hp]` 存僵尸，而每回合入场的僵尸恰好落在上一只的下一格，`zombies[nxt] = zombies.pop(c)` 每回合覆盖并吞掉一只。它仍能输出「看起来合理」的曲线（开局连错 7 题 → 失败），而正确模型是 **4 题**。GDD 的失败门槛表、`epics` 的 AR23、以及「递增阳光不改变失败门槛」这一结论**全部出自这个 bug**。

**这类 bug 不报错、不崩溃，产出的数字「像模像样」—— 比崩溃更危险，因为下游会拿它当论据。**

**守卫** ⚠️ **无守卫（balance-sim 侧）**。最近似的 `tests/components/battle-field.test.ts` G17b（「每只 `state.zombies` 里的僵尸都渲染出且只渲染出一个元素」）守的是组件渲染层，不是模拟器。

**首现** Story 1.5

### R-24 网格列号 0-based 是内部唯一口径

**规则** 内部一律 0-based。需要给用户看的列号（UI、题面）另行换算，并在守卫里成对断言（如「索引 8 = 界面第 9 列」）。

**依据** 混用两套编号是 off-by-one 的头号来源。房子列索引 0 = 界面「第 1 列」。

**守卫** `tests/core/grid.test.ts`（入场列索引 8 = 界面「第 9 列」；房子列索引 0 = 界面「第 1 列」）、`tests/components/battle-field.test.ts`（「M44：僵尸的列号按 0-based 渲染」）

**首现** Story 1.4
